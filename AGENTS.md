## The Prompt System

The `prompt` command is a **native C++ dispatcher** — source in `prompts/`, installed to `bin/prompt` (see ["`prompts/` — native prompt dispatcher (C++)"](#prompts--native-prompt-dispatcher-c) below). It builds a fixed set of prompts into the binary and does **not** scan for `.sh`/`.txt`/`.md` files at run time. Output is auto-copied to the clipboard (a prompt opts out by setting `r.no_clipboard`).

```bash
prompt <name> [-- args...]       # run a prompt
prompt list                      # list prompts + short descriptions (--names for bare names)
prompt list-prompts              # print the full help of every prompt
cat file.cpp | prompt fix        # pipe input to a prompt
echo "task" | prompt auto        # auto-detect best prompt from input
```

`list` and `list-prompts` are ordinary native prompts (`prompts/src/prompts/list.cpp`, `list_prompts.cpp`), not special cases in the dispatcher.

Argument tokens that match a prompt name — optionally prefixed with `.` or `-` — start a chained prompt: `prompt .tse فولاد .note "compare with فخوز"` runs `tse`, then `note` (`.files` embeds files generically, `.note` appends a note, `.cli` a CLI hint). Without piped stdin the dispatcher runs independent chain segments in parallel (in forked children, so the prompts' own subprocesses never fork from a multi-threaded parent) and appends their results in argv order. Piped stdin keeps the chain sequential: chained prompts do NOT receive the previous prompt's output on stdin — each sees the original pipe, which is spent once a prompt that reads stdin has consumed it (the dispatcher separates segments with blank lines and copies only the combined output). The `tse`-family data prompts share a symbol, so `.tse.codal`/`.tse.intraday` borrow a neighbouring `.tse*` argument before consulting the clipboard: `prompt .tse foolad .tse.codal .tse.intraday .tse.analyze`. Analysis prompts compose by chaining: `prompt .tse فولاد .tse.analyze` is the data prompt plus the data-free analyst instructions, so the dataset is embedded once.

**Prompt files (`*.prompt`)** — the same shorthand can live in a file: `prompt debug.prompt` runs the file's tokens as if they had been typed after `prompt` (an argument token ending in `.prompt` that names a readable file is replaced, in place, by the tokens it holds, so `prompt .note "context" debug.prompt .length short` works too). A file is split on spaces and newlines, `#` at the start of a token comments out the rest of its line, `"..."` (with `\"`/`\\` escapes) and `'...'` quote, and nothing else is expanded — no `$VAR`, no globbing, no command substitution. A name is looked up next to the file that named it (the current directory at the top level), then `<git-root>/.prompt/`, then `$XDG_CONFIG_HOME/prompt/prompts`; files may include other files (8 levels deep, cycles rejected), a leading `prompt` token is dropped, and everything after `--` is copied verbatim. `prompt --no-prompt-files ...` turns the pass off. The tokenizer and resolver live in `prompts/src/sdk/prompt_file.cpp` and run before chain parsing, so sinks, `.each` bodies and the history store only ever see an ordinary argv.

**Function steps (`prompt .func NAME(params) ... .end`, called as `.name`)** — the third kind of chain step, next to prompts and sinks: a named, parameterized chain template the user defines and invokes exactly like a prompt. The signature is a single token (`NAME` or `NAME(p, p=default)`, no spaces inside the parens); a call fills the declared params by position or with `--name value`/`--name=value`, `{name}` in the body is a value, `{@}` (as a whole token) the positionals past the declared ones, `{0}` the function name and `{N}` the Nth argument, and a `{field}` that is not a parameter is left for `.each`. Definitions live in the command, in a `.prompt` file, or in `funcs` files (`<git-root>/.prompt/funcs` then `$XDG_CONFIG_HOME/prompt/funcs`, project over user; `PROMPT_FUNCS` replaces the list, an empty value disables them). A function may not shadow a built-in prompt or sink, and a bad definition is a hard error (exit 2). The pass lives in `prompts/src/sdk/function.cpp` and runs after prompt files and before chain parsing, so sinks, `.each` bodies and the history store only ever see an ordinary argv.

**Shell completion (`--complete`, `--complete-line`)** — every candidate a shell offers comes from the binary, not from the fish script: `shell/completions.fish` forwards the command line (`prompt --complete-line <current> <tokens after prompt>`) and prints what comes back, while the dispatcher classifies the position itself. At the head (nothing matched yet) it offers its own flags, every prompt name in the three spellings (`.name`/`-name`) and the `*.prompt` files it can inline there (the current directory, then `<git-root>/.prompt/`, then `$XDG_CONFIG_HOME/prompt/prompts`, each candidate naming its source, nearest winning a name they share; a token containing `/` lists that directory instead, subdirectories included, so the user can descend); a `.name`/`-name` token starts the next step, and anything else is an argument of the open prompt. Functions complete like prompts: `.func` is offered at the top level and `.end` inside a `.func` body (which completes as a chain), and the names come from the global `funcs` files plus the `.func … .end` blocks defined earlier (the line is run through the `*.prompt` pass first, so a definition in an inlined file is found). A `.exec --` tail and an open `.each` body are left to the shell's own path completion, and at an argument position the dispatcher's candidates sit on top of it, so `.files src/ma<TAB>` still lists files. `prompt <name> --complete <prefix> [args...]` remains the single-prompt form (the flags derived from that prompt's own help plus its `complete_fn` callback, e.g. `tse.resolve --complete` for instrument names). Both print `value<TAB>description` lines and are answered before the clipboard is initialized and before stdin is read, so completion never runs a prompt. `--no-prompt-files` suppresses the file candidates.

**Prompt sinks (`ai.*`)** — `.ai.chatgpt`, `.ai.dseek`, `.ai.gap`, `.ai.grok`, `.ai.kimi`, `.ai.lms`, `.ai.openai` and `.ai.debate` are chain **sinks**, not ordinary prompts: they wait as a barrier for every segment before them, send the accumulated stdout to the site (or, for `.ai.lms`/`.ai.openai`, to an OpenAI-compatible HTTP endpoint), and (by default) replace the context with the answer for later segments. Position them anywhere: `prompt .note "review this" .files src/main.cpp .ai.dseek .note "now list the risks" .ai.grok` runs the files batch, asks DeepSeek, then asks Grok about DeepSeek's answer. `.ai.debate grok dseek` is the relay variant: it asks the first AI, passes its answer to the next one as `Another AI said:` with a verification request, and keeps alternating for `--rounds N` (or until every AI's `VERDICT:` line agrees with `--until-agree`), leaving the last answer (or the labelled transcript with `--context all`) as the context. Shared sink flags are owned by the dispatcher and identical for every sink: `--on-error abort|continue|skip` (default `abort`; a failed source batch taints the context and each later sink applies its own policy), `--with-context` (append the answer instead of replacing), `--show-context` (print the source segments too; the default output is sink answers plus any trailing segments no later sink consumed) and `--head N` (trim the context). Reasoning goes to stderr and is never chained. `--print-prompt` on an `ai.*` sink is an offline dry run that prints exactly what it would send. Instructions belong in a preceding `.note` or `--system`; positional prompt text is rejected because stdin carries the chain. Sinks also stream their stdout/stderr live; the stored context and clipboard are sanitised.

**Save sink (`.save`)** — `.save [FILE|DIR]` is a passthrough sink: it writes the accumulated chain context (the same sanitized, `--head`-trimmed text an AI sink receives) to disk and leaves the context unchanged, so it can sit before `.ai.grok` without altering what Grok sees. `prompt .tse khodro .tse.codal .save` writes `tse-khodro.md` in the current directory; `.save /tmp` writes `/tmp/tse-khodro.md`; `.save report.md` writes exactly that path. The name comes from the nearest successful preceding prompt's `keys::save_stem` fact (`tse-<symbol>` from the `tse` family, the snapshot stem for `.stock` input, the first embedded file's stem from `.files`, a `.delegate`/`.extract` binding), falling back to a timestamped `prompt-YYYYMMDD-HHMMSS.md`. A `.save` with **no explicit target** declares `keys::save_wants_name`, so a preceding `.delegate` additionally asks the AI to name the file (a `filename:` field in its reply, extracted into `keys::save_stem` by the published plan); an explicit `FILE`/`DIR` suppresses that request. Hints are basenames only and are sanitized by `.save`. Existing files are refused unless `--force` is passed; `--allow-empty` writes an empty context. Status goes to stderr, never the chain or clipboard. `.clear` is the reset counterpart: it drops the context, the filename hint, the redaction note and the failure taint for later segments while keeping the output and clipboard already produced, so one invocation can run independent sections. `.flush [FILE|DIR]` combines the two (`.save` followed by `.clear`) and clears only after the write succeeds.

**History store (`.history*`)** — the dispatcher records every invocation under `${XDG_STATE_HOME:-~/.local/state}/prompt/runs/`: one append-only Markdown file per run (`<YYYYMMDD-HHMMSS-t<mm>-<xxxx>>.md`) whose `<!-- history:run|segment|end {json} -->` markers hold the command line, the cwd/git root, the terminal it ran in and each segment's own output as a delta (its exact bytes, the barrier input when it differs from the replayed context, args, body, merge, exit status, redaction flag). `.history [ID|RANK] [--segment NAME|INDEX] [--input] [--all] [--meta] [--head N]` is an ordinary prompt that prints a stored run — by default the emitted text exactly as it went to stdout/clipboard, so the answer to `prompt .verify .ai.dseek` is retrievable later as `prompt .history`, chainable into `.save`/`.ai.grok`, or piped. `.last` (alias `.history.last`) is the terminal-scoped form: it prints the newest run from the invoking terminal — the session id (`getsid(0)`, with the controlling tty recorded beside it) that every run marker stores — so concurrent terminals never collide, and it falls back to the globally newest run with a one-line stderr note when this terminal has none (`--any` forces the global view); `.history` takes `--here` for the same scoping. A bare integer is a rank (1 = newest) when one could exist (`1..count`), otherwise it is read as an id prefix (so `20261024` selects that day's newest run); `--segment` picks one segment's own output, `--input` the context a sink saw, `--all` every segment, `--meta` the header (including the terminal), `--head N` trims. `.history.list [--limit N] [--since DUR] [--paths] [--json] [--here]` lists runs newest-first, `.history.find QUERY [--regex] [--case-sensitive] [--name NAME] [--since DUR] [--limit N] [--context N] [--paths] [--json] [--here]` searches segment text and command lines (exit 1 when nothing matches), and `.history.dir` prints the store directory. The store is pruned automatically on each run (oldest first, never the run in progress): 1000 runs / 256 MiB by default, or `--keep`/`--max-size`/`--older-than`/`--all`/`--dry-run` on `.history.purge`. `.history*` prompts are never recorded themselves (their descriptor sets `record = false`); a child run (an `.each` item or `.exec` chain) is tagged `parent` with the invoking run's id; a store write can never fail a prompt run. Env knobs: `PROMPT_HISTORY` (0/off disables recording), `PROMPT_HISTORY_DIR`, `PROMPT_HISTORY_MAX_BYTES` (4 MiB per file), `PROMPT_HISTORY_KEEP`, `PROMPT_HISTORY_SIZE`, `PROMPT_HISTORY_INNER` (0 = do not record child runs), `PROMPT_HISTORY_PRUNE` (0 = no automatic pass), `PROMPT_HISTORY_CURRENT`, and the terminal identity `PROMPT_TERMINAL_SID`/`PROMPT_TERMINAL_TTY`/`PROMPT_TERMINAL_KEY` (see `sdk/terminal.hpp`).

**Key prompts:**
- `auto` — dispatches to the right prompt based on input heuristics (compiler output, YouTube URLs, Dockerfile, CI config, language detection)
- `fix` / `review` / `tests` / `refactor` — general code analysis
- `cpp` / `cpp-reviewer` — C++ specific (auto-detects compiler errors)
- `run` — runs `bin/run`, embeds output for debugging
- `clipboard` / `c.p` / `c.c` — clipboard integration: `.clipboard` (alias `.c.p`) is a source that reads the clipboard into the context (`--head N` caps it, counting real content lines because the pasted text is trimmed of its blank edges first; an optional `paste` subcommand is accepted), and `.c.c` is a passthrough sink that copies the accumulated chain context to the system clipboard (`prompt .note "remember this" .c.c`). A source never receives the chain context, so `copy` cannot be a subcommand of `.clipboard` — it is the sink `.c.c`.
- `length` — sets how long the AI's answer should be. A number with an optional unit (words by default: `200`, `10 lines`, `3 paragraphs`, `500 chars`, `300 tokens`, `2k`, `200w`, `--words 200`, `a few sentences`) or a preset: length presets (`tiny`, `short`, `medium`, `long`) and shape presets (`one-liner`, `sentence`, `paragraph`, `bullets`, `title`, `tweet`, `sms`, `email`, `letter`, `blog`, `article`, `report`, `essay`, `abstract`, `outline`, `notes`, `caption`, `bio`, `commit`, `changelog`, `thread`, `tldr`); with no target it defaults to `medium` (about one or two paragraphs). Approximate by default; `=200`/`--exact` asks for a hard target, `--max`/`--min` only caps or only extends. Chain it like any instruction: `prompt .fix src/main.cpp .length 200`, `prompt .tse فولاد .tse.analyze .length long`, `prompt .note "explain the design" .files a.cpp .length blog`.
- `expect` — state the exact response shape for an AI answer and publish it for the extraction stage. Each argument is `[NAME=]SELECTOR`, where `SELECTOR` is the shared `md.extract` grammar (`table[:col1,col2]`, `code[:lang]`, `section[:heading]`, `command[:program]`, `field:LABEL`, `frontmatter`, `any`, `auto`, `none`, `@N`); exactly one **unnamed** entry is the primary (it replaces the context) and every named entry is published as that fact after extraction. The contract for all entries is appended to the chain context, so the next `.ai.*` sink sees it, and `.extract`/`.exec`/`.each` reuse the published plan (a single unnamed selector keeps the old one-value behaviour). `prompt .note "screen TSE banks" .expect table:symbol,reason .ai.dseek .extract`; `prompt .expect command:prompt save.stem=field:filename .ai.dseek .extract .save` asks for a `prompt …` command **and** a filename, saving under the AI-chosen name.
- `extract` — a sink that takes one table/code block/section/command/field out of the accumulated context with `bin/md.extract` and replaces the context with it, publishing every named binding of the `.expect`/`.delegate` plan as its fact (so `save.stem=field:filename` names the next `.save`). No selector means the published plan, then `auto` (the only candidate); `--list` shows candidates on stderr and keeps the context, `--json` returns block records, `--pick` opens fzf. `prompt .note "give me the diff" .ai.dseek .extract code:diff | git apply`
- `exec` — a sink that runs one command and continues the chain with its output. With no command it extracts one from the AI answer (`selector → .expect/delegate shape → auto`), and a context that is exactly one `prompt …` line runs that chain directly, so `… .extract .exec` works; otherwise `-- COMMAND [ARG…]`. No shell: direct arguments are verbatim, an extracted or quoted command line is split with quotes/backslashes only, and `|`/`>`/`&&`/`$()` are refused. Approval is policy-driven (`~/.config/prompt/policy`, `<git-root>/.prompt/policy`, built-ins for `tse*`/`md.extract`, destructive programs denied); a generated `prompt` chain is shown whole, `--yes` allows asks but never a deny, and `--print` previews. Put `--` before a direct `prompt` chain: `prompt .exec -- prompt .tse foolad .tse.analyze`
- `each` — loop a chain body over items with `prompt … .each [SELECTOR] [flags] BODY .end`. Items come from `md.extract --items` (table rows, code blocks, sections, commands); `{symbol}`/`{field}`, `{item}`, `{body}`, `{index}`, `{n}` and `{file}` are substituted into the body, which runs as one child `prompt` per item (parallel, `-j N`) so each item can fetch, ask an AI and save independently. Nested loops and bodies are depth-counted; item data can never become a prompt name or `.end`. `--print` previews the substituted commands, `--list` shows the items, `--stdin` feeds each item's text to the child, `--json` reports per-item results. Example: `prompt .note "screen banks" .expect table:symbol .ai.grok .each table:symbol .tse {symbol} .tse.analyze .end`
- `history` — print a recorded prompt run (the text a previous invocation produced) by id, rank or segment and chain it like any source (`prompt .history`, `prompt .history 1`, `prompt .history --segment ai.dseek`, `prompt .history .save answer.md`); `history.list` / `history.find` browse and search the store, `history.purge` prunes it, `history.dir` prints its path; `.last` (alias `.history.last`) is the terminal-scoped shortcut for the newest run *from this terminal*, so a later invocation can chain this terminal's last answer (`prompt .last .note "compare with the above" .ai.chatgpt`), and `--here` scopes the other three to this terminal
- `tse.analyze` — the **data-free** institutional-analyst instructions for the dataset collected by `tse` (corporate/fund analysis, market context, order-book and حقیقی/حقوقی flow reading, Codal checks when chained, scenario plan). It takes no arguments and never fetches: chain it after the data prompt, `prompt .tse فولاد .tse.analyze`; add `.tse.codal` when Codal filings are needed (`prompt .tse فولاد .tse.codal .tse.analyze`). This lens carries no data collection of its own, so the dataset is never embedded twice.
- `tse.analyze.history` — the **data-free** historical base-rate lens for the same dataset (established uptrends, mid-trend corrections and sideways consolidations, every qualifying episode enumerated structurally rather than by outcome, identical per-episode metrics from adjusted closes and daily حقیقی/حقوقی flow, the current episode against them, and an accumulation verdict with raw price triggers). Takes no arguments and never fetches: `prompt .tse فولاد .tse.analyze.history`, optionally followed by `.tse.rigor`; it uses the `## Historical corrections / اصلاحات تاریخی` section `tse` precomputes and does not re-sum the CSV.
- `tse` — gathers TSETMC market data via `bin/tse` (plus market context: USD/IRR, Iran inflation/GDP, whole-market breadth for the newest session and the five before it, per-instrument statistics, derived technicals, historical corrections/consolidations with their flow and outcomes, the last session's auction/close order books) as the raw Markdown dataset (live fetch or `.stock` snapshots), with **no analysis instructions**: for piping, chaining or the analyst lens (`prompt tse فولاد .note "compare with فخوز"`, `prompt .tse فولاد .tse.analyze`); accepts a Persian symbol, ISIN, insCode or easytrader/tsetmc/codal URL, borrows a neighbouring `.tse*` argument (then the clipboard) when omitted, full history by default (`--days N` to limit, `--without book,statistics,breadth,corrections` to skip a section); Codal filings are **not** fetched — chain `.tse.codal` (it borrows the symbol) when they matter; one or more `.stock` snapshot files (written by `bin/tse.snapshot`) build the identical prompt from cached data — snapshot data goes through the same Markdown renderer as a live fetch (CSV history, compact sections) behind an `Instrument:` header — warning when older than 24 hours (`prompt tse stocks/14050717_فولاد_IRO1FOLD0009.stock`); shares its data-collection code in `prompts/src/prompts/tse_data.hpp`
- `tse.codal` — the **data-only** Codal dataset from `bin/tse.codal` (announcements, extracted statement rows, monthly fund portfolio reports, derived ratios), with no analysis instructions. Accepts the same identifiers as `tse` (through `tse.resolve`) plus chain/clipboard fallback, `--top N` (1–20), `--fund`, `--refresh` and `--head N`; results come from Codal's six-hour cache unless refreshed. Chain it between the market data and the lens: `prompt .tse فولاد .tse.codal .tse.analyze`.
- `tse.intraday` — per-minute bars for one instrument, fetched with `bin/tse.intraday`, as raw Markdown with **no analysis instructions** (`prompt tse.intraday فولاد`); the prompt and the tool share the name, so the embedded data is exactly the tool's output (bars rebuilt from the per-trade tape, VWAP, official daily row, each session's high/low times, opening ranges, value area and largest prints, daily حقیقی/حقوقی, opening-auction/close order-book summaries, market breadth, instrument statistics, today's price limits, optional `--depth`); same identifier forms and chain/clipboard fallback as `tse`, with `--days N` (max 30), `--date`, `--from/--to`, `--interval`, `--depth`, `--no-live` and `--head N`
- `tse.intraday.analysis` — the **data-free** same-day trade lens for that dataset (LONG or NO-TRADE with a numeric plan); it takes no arguments and never fetches, so chaining `prompt .tse.intraday فولاد .tse.intraday.analysis` embeds the dataset once and then these instructions (the same split as `tse`/`tse.analyze`)
- `tse.rigor` — a market/TSE analysis and backtest honesty checklist (compute ratios from a table, no look-ahead bias, mandatory baseline/median/expectancy stats, explicit left-tail risk); standalone or chained (`prompt tse فولاد .tse.rigor`)

## `prompts/` — native prompt dispatcher (C++)

The `prompt` command is a native C++ dispatcher. **One file = one prompt:** each `src/prompts/<name>.cpp` implements its prompt and registers itself, so there is no central list and no prompt files are scanned or executed at run time. A subtree guide lives in `prompts/AGENTS.md`.

- Build: `cmake -S prompts -B prompts/build -DCMAKE_BUILD_TYPE=Release && cmake --build prompts/build -j 8` (the build type is not defaulted — a bare configure yields an unoptimised binary); Debug build with tests: `prompts/build-asan` (`ctest` there must pass)
- Install: `cmake --install prompts/build --prefix "$HOME/cmd" --component prompt` writes `bin/prompt` (gitignored; the `prompt` component keeps the FetchContent'd `httplib`/`date` out of the prefix). Because `~/cmd/bin` is on PATH, `prompt` then runs the native binary, and the executable's own directory is `bin/` — which is also how `fs::bin_tool` finds its sibling `bin/` tools without shelling out
- Format: clang-format (`clang-format -i` over `prompts/**/*.{cpp,hpp}`; `--dry-run -Werror` must be clean)
- Lint: clang-tidy via `.clang-tidy` (`clang-tidy -p build src/*.cpp src/*/*.cpp tests/*.cpp`); must report zero warnings. Its `--fix` mangles long single-line statements in headers, so fix one file at a time and compile after each
- Chain semantics: prompts in a chain share the ORIGINAL piped stdin (nobody feeds a prompt's output into the next), segments are folded by one rule — `text::append_block`, shared by the chain context, stdout, the clipboard and the history replay: each segment's text is trimmed of leading and trailing newlines, an empty segment contributes nothing, consecutive blocks are separated by exactly one blank line, and the whole output ends with one newline — and a prompt that reads stdin spends the pipe for later prompts with `v.in.spend()` (reported through `segment_outcome::stdin_consumed`, or `prompt_error::stdin_consumed()` when the prompt threw). `.each … .end` owns a raw body (`takes_body`), and `.exec -- COMMAND…` owns the rest of argv so a child `prompt` chain is not parsed as outer segments; a missing/unexpected `.end` is a parse error (exit 2)
- **Agentic layer:** `.expect` (response contract + a `keys::expect` **plan** of `[NAME=]SELECTOR` entries: one unnamed primary plus named bindings), `.extract` (selection sink that publishes the named bindings as facts), `.exec` (command sink), `.each … .end` (parallel loop sink). Extraction/contracts live in `bin/md.extract` (`--select`, `--items`, `--contract`, `--kinds`, the `field:LABEL` selector); the native prompts only call it. `.exec`/`.each` use the plan's primary entry. Commands are gated by `sdk/policy.*` (user `<git-root>/.prompt/policy`, `~/.config/prompt/policy`, env overrides, built-ins; deny wins ties; `--yes` allows asks); prompts are trusted but generated `prompt` chains are approved whole. Loop items run in child processes (`PROMPT_INNER=1`, `PROMPT_INNER_DEPTH` capped at 2) and the parent owns the clipboard/redaction legend
- Prompts that shell out (`run`, `spp`, `gtest-case`, `clang-tidy`, `git*`, `tse*` via `bin/tse`/`bin/tse.intraday`, `skill`, `yt`, …) must preserve the tool's exact output text and error routing (`tse: <msg>` exit 1, usage errors to stderr). Repo utilities are located with `fs::bin_tool` (exe dir → git root → cwd walk → `$PATH` resolved to an absolute path), never re-implemented inside a prompt
- **The segment contract:** a prompt is `static void execute_<name>(view const& v, result& r)`. The read-only `view` holds `v.name`, `v.args`, `v.in.text()`, `v.env.git_root`/`v.env.exe_path`, `v.text` (the accumulated chain context a sink reads), `v.prior` (facts earlier segments declared or published) and `v.stream`; the `result` holds `r.out` (stdout, sanitised/pipelined/clipboarded), `r.err` (stderr, exit stays 0), `r.stderr_buffer` (sink streaming only), `r.published` (facts later segments read, `keys::` constants in `sdk/facts.hpp`), `r.no_clipboard` and `r.clear`. A prompt never mutates chain state. It *throws* on failure: `usage_error` (exit 2), `soft_error` (exit 1) or `prompt_error` (`exit_code`, `message` for stderr, `partial_output` for stdout printed before the failure, `no_clipboard`, `stdin_consumed`). The dispatcher catches them once in `main.cpp`'s chain loop (a failed prompt's partial stdout is still accumulated, the chain continues, first non-zero status wins). No prompt declares `noexcept`; functions that can throw say nothing.
- **Subprocesses:** `process::command` (fluent builder) or `run_command(argv, stdin, env, timeout)` — fork/exec, no shell, no quoting; `stderr_mode` picks inherited (the default: the tool's diagnostics appear as it runs) / captured / `2>&1`. `execvp`-style argv means an argument with spaces, quotes or newlines reaches the child intact. `run_script()` is the `/bin/bash -c` escape hatch. Tests: `tests/test_errors.cpp` (error surface), `tests/test_chaining.cpp`, `tests/test_fs.cpp` (`fs::bin_tool` layout/PATH resolution).
- **SDK helpers:** `src/sdk/args.hpp` carries the boilerplate the prompts used to repeat — `head_lines_or_throw(v, strict)` (the `--head` parse plus the `throw usage_error{…}` preamble) and `file_options_or_throw(v, strict)`, the file prompts' whole CLI: the validated `--head N` cap plus the value-less `--num`/`--numbered` line-number flag (spellings in `kNumberFlags`, tested with `is_number_flag(arg)`), returned as a `file_options {head_lines, numbered}`. `positional_args(v)` returns the arguments with the `--head <value>` pair and the `--num`/`--numbered` flags removed; `collect_file_args(v)` splits FILE arguments into the regular files to embed and the missing ones to warn about. `embed.hpp` has `number_lines(text, numbered)` (the `N | line` prefix `--num` enables) and the embed helpers take the `file_options` struct. Help text is generated from `file_usage_help(...)` / `file_options_help(...)` so every file prompt's usage and `--head`/`--num` block stay identical. `prompt::environment` is a plain data bag built once by `prompts/src/environment.cpp`'s `make_environment()`; its services are free functions taking it (`clipboard_content`, `clipboard_identifier`, `select_files`, `resolve_input_file`) and the pasted-text → instrument policy lives beside the clipboard it reads (`core/clipboard.cpp`'s `clipboard::detect_identifier`), and `infer_lang` returns `std::string_view`. `sdk/stage.hpp` defines `view`/`result`/`declaration`, `sdk/facts.hpp` the fact store, `sdk/wire.hpp` the fork codec (`segment_outcome`, `drain_all`), and `sdk/chain_state.hpp` the dispatcher's text fold
- **Redaction legend:** `sanitize::sanitize()` returns `{text, redacted}`, and when `clean_privacy` rewrites any personal data (`HOME`, `USER`, `HOSTNAME`, `IP_ADDRESS`, `MAC_ADDRESS`, `EMAIL_ADDRESS`, `PHONE_NUMBER`, `SSN`) `main.cpp` prepends one line (`sanitize::kRedactionLegend`) to the accumulated stdout and clipboard before printing, so the model knows the placeholder tokens are redactions, not the original text. Tests: `tests/test_sanitize.cpp`
- **No embedded Python:** live TSE fetches shell out to `python3 bin/tse all … --markdown` and intraday bars to `python3 bin/tse.intraday` (the tools' stderr is inherited), `.stock` snapshots go through `bin/tse snapshot`/`bin/tse markdown` (the same renderer, so cached and live data match), skill frontmatter is parsed in C++, and the KDE clipboard path calls `qdbus` — nothing links libpython
- Adding a prompt: write `src/prompts/<name>.cpp` implementing `static void execute_<name>(view const& v, result& r)` and `static void render_help_<name>(std::ostream&)`, then end the file with one self-registration call — `bool const registered = prompt::register_prompt("<name>", "<summary>", &execute_<name>, &render_help_<name>);` (CMake globs the sources; no other file changes). The `<summary>` is the first paragraph of the help text, verbatim, and is what `prompt list` prints. Registration runs at static-init time, which is why `prompt_lib` must stay an OBJECT library (a static archive would drop the otherwise-unreferenced registrar objects); the name is passed explicitly because dotted/dashed names (`git.diff`, `tse.find`, `fs8.mod`, `clang-tidy`) can't be derived from the identifier. The registry is a fixed array of `prompt_registry_capacity` (128) slots: registering more aborts at startup with a message instead of silently dropping a prompt, and the chaining test asserts the catalog fits. `prompt list`/`--help`/`list-prompts` come straight from `render_help_fn`
- `prompt new` embeds the SDK headers and one example prompt so an AI can write a consistent new one. Those snapshots are **generated at build time** — `cmake/embed-assets.cmake` bakes the files listed in `PROMPT_ASSETS` (`CMakeLists.txt`) into `${CMAKE_BINARY_DIR}/generated/prompt_assets.hpp` as raw strings, so the binary never reads the source tree at run time yet can't go stale; add a header there (and to `PROMPT_ASSETS`) when the guidance should include it
- `list`/`list-prompts`/`delegate` order the catalog with `prompt_descriptor_less` (locale-aware `std::strcoll` over the prompt names, shared by all three)

Sinks render like a direct run — `bin/ai --tty` is passed when prompt's stdout is a TTY, and the chain context and clipboard are read back from a hidden `--context-file`, so no ANSI/Markdown frames leak into them. Tool calls are display-only, never executed. `-f`/`--file` (repeatable) uploads a local file through the site's own endpoint and attaches it to the first message (announced as an `upload` tool event); `bin/ai/files.py` reads/names/types it. A prompt over the provider's inline budget (ChatGPT 48 KiB, GapGPT 24 KiB, Grok 64 KiB, DeepSeek/Kimi 256 KiB, in UTF-8 bytes) is written to a temporary `.txt` by `bin/ai/promptfile.py`, uploaded through the same path and replaced by a short pointer message; `--prompt-file` forces it, `--no-prompt-file` keeps the prompt inline and `--prompt-limit BYTES` overrides the budget. Size-limit errors (`HTTP 413`, GapGPT `token_limit`, the sites' context/conversation messages) are annotated with the prompt size and the remedy (drop `--no-prompt-file`, lower `--prompt-limit`, or trim the prompt). `-i` chats in a loop and `-c`/`--continue` (or `--new`) reopens or replaces the last conversation, remembered under `$XDG_STATE_HOME/ai/<provider>.json` by `bin/ai/state.py` — ChatGPT, DeepSeek, GapGPT and Kimi resume by conversation/message id (Kimi's server keeps the transcript), Grok (per-process socket) replays the stored transcript. - `ai.debate` — the relay variant of the same engine (`bin/ai/debate.py` + thin entry): two or more providers answer the same question in turn, each seeing the newest other answer as `Another AI said:` plus a verification request, with every participant keeping its own conversation. `ai.debate grok dseek` (question on stdin or after the providers) defaults to `--rounds 2`; `--until-agree` stops after a pass in which everyone's `VERDICT: AGREE` line agrees, `--instruction TEXT`/`--no-instruction` override the request, `--context last|all` (`--transcript`) picks what the sink context/clipboard receives, `-c`/`--new` resume or discard the saved per-provider chats of the last debate between the same providers, `-m PROVIDER=MODEL` chooses models per side, and `--print-prompt`/`--print-session`/`--list` are the offline dry runs. The relay accepts the API providers (`lms`/`lmstudio`, `openai`/`oai`) alongside the web ones (`--base-url`/`--api-key`/`--param` reach them), loading each provider's session only when it needs one. A failed or empty turn stops the relay with the last complete answer in the context file, and each provider's `-f` attachment goes to its first turn. It has a native sink too (`.ai.debate`), so a prompt chain gets the same `--with-context`/`--on-error`/`--head` handling and a `--context-file` side channel as `.ai.*`; `.ai.debate`'s completion callback offers the provider names (and `PROVIDER=` after `-m`/`--model`).
- `ai.lms` / `ai.openai` — the same engine over an **OpenAI-compatible HTTP API** (`bin/ai/providers/openai_compat.py`, one SSE mapping for `text`/`reasoning_content`/tool calls/usage) instead of a website session: `ai.lms` talks to a local **LM Studio** server (no key), `ai.openai` to `api.openai.com` (`$OPENAI_API_KEY`) or any compatible endpoint via `$OPENAI_BASE_URL` (OpenRouter, Groq, vLLM). `ai.lms` finds its endpoint from `--base-url`, `$LMS_BASE_URL`, the cached one (`$XDG_STATE_HOME/ai/lms-endpoint.json`), a probe of the usual local ports (`1234`, `1337`, `8080`, `8000`, `11434`, checking `GET /v1/models`) and finally `lms status`, then caches it; the model comes from `-m`/`$LMS_MODEL`/`$OPENAI_MODEL`, falling back for `ai.lms` to the first chat model the server lists (`/api/v0/models`, which marks the loaded one and hides embeddings) while `ai.openai` insists on an explicit model. `--param KEY=VALUE` passes any extra inference parameter through, `--print-session` reports the endpoint/model/reachability as JSON, and the providers are **stateless**: `-c`/`--continue` and `-i` replay the saved transcript (via `bin/ai/state.py`) as the request's `messages`. There is no upload endpoint, so `-f` inlines the file into the message (text as a fenced block headed `File: <name>`, images as `image_url` data URLs, other binaries refused) and `--prompt-file` is a usage error with that remedy. Both are native prompt sinks too (`.ai.lms`, `.ai.openai`), and `bin/ai/net.py` reads the error *body* of a streaming failure so the message keeps the server's own reason.
- `browser.session` — compose a site's authenticated session (cookies + web storage + UA) through `cookies`/`browser.storage`/`browser.find`; the sign-in source for the web `ai.*` providers
- `accounts` — cross-browser account manager: a named identity per site (`x.com/work`) stored under `${XDG_DATA_HOME:-~/.local/share}/accounts` (0700/0600) and installed into a *profile* (`browser/profile`, e.g. `firefox/default-3`) with `add`/`install`/`open`/`logout`/`diff`/`forget`/`undo` (`add` captures a login out of a profile, or logs one in in a throwaway `--user-data-dir` when no profile holds the site yet; `install` is an exact replacement, `--merge` additive; `open` installs and launches). Bundles carry cookies **and** `localStorage`, decrypted so one bundle moves between Chromium and Firefox; Chromium values are re-encrypted with the target key only when it is *verified* against a stored cookie, otherwise written to the plaintext `value` column (Chromium reads both; an unverified keyring key silently loses the cookie). Writes require the profile to be closed (`--close` SIGTERMs it first), are backed up per profile for `undo`, and `--dry-run` prints the exact row/key operations. `--dedicated` (and `new-profile`) create a dedicated `accounts-<label>` profile (registered in Firefox's `profiles.ini`, visible in both pickers); `--at BROWSER[/PROFILE]` names a profile (a bare browser means its default), and without it the profile is auto-detected — the account's recorded profile, then the only profile that actually holds the site's cookies/`localStorage` (counted, never decrypted), then an `fzf`/numbered picker on a terminal (`--pick` forces it and reads stdin, `--no-pick`/`--json` turn it into an error listing the candidates with their counts). Chromium `localStorage` is written by appending a LevelDB write-ahead-log batch (`Local Storage/leveldb/*.log`, no `plyvel`), Firefox by updating `storage/<default|permanent>/<origin>/ls/data.sqlite` (the origin dir must already exist; a fresh profile warns and applies cookies only). Saved passwords are deliberately not moved.
- `ai.save` — local, git-backed Markdown store for the same five providers (`bin/ai/save/` package + thin entry): syncs chats through `browser.session` (no `auth.json`), one file per chat under `topics/<topic>/<YYYY-MM>/<date>_<title>.md` with JSON frontmatter and invisible per-message `<!-- ai.save: {...} -->` markers, and a committed `months/<YYYY-MM>/<topic>` relative-symlink view. `sync` is incremental (sidebar summary, then fetch only new/changed; `--full/--limit/--jobs/--retries/--retry-delay/--dry-run/--provider/--force`), categorises with ordered `.ai/config.json` rules (`where` = title/content/any/provider/project, regex patterns, `min_code_blocks`, GapGPT project names) and preserves manual categories/tags. `last` answers "what was the newest saved message?" by scanning frontmatter (current year plus older month dirs touched this month, with a stat-based guard; `--all`, `--by saved`, `--role`, `--kind` (defaults to `text`), `--chat`, `--json`), `list`/`show` browse, `add`/`reply` save prompts/responses from files or stdin (appending marks `local_edits`, so sync skips the chat unless `--force`), and `categorize`/`tag`/`untag`/`recategorize`/`categories`/`rename-category`/`remove`/`reload`/`verify`/`migrate`/`relink`/`providers`/`config` maintain the tree. Every mutation commits to git (`--no-commit` opts out); there is no database or manifest — Markdown/frontmatter is the source of truth. `--provider` accepts the registry keys plus aliases (`gapgpt`/`gap-gpt` → `gap`, `dseek` → `deepseek`), and `list`/`last` reject unknown names; the keyless API providers (`lms`, `openai`) are not recordable and are refused. GapGPT's history listing retries a stalled project/page in place and skips it (reported as `incomplete` in the sync JSON) instead of aborting the whole provider.

**Market data:**
- `tse` — TSETMC quotes, order book, individual/legal (حقیقی/حقوقی) flows with their share volume, rial value and trader counts, history, derived technicals (returns, realised volatility, ATR(14), MA20/50/200, RSI(14), 52-week position, drawdown, median gap), fundamentals, per-instrument statistics, whole-market breadth for the newest session and the five before it, the last completed session's opening-auction and close order books (the same validated `BestLimits` stream `tse.intraday` replays), and market context for `prompt tse`/`prompt .tse.analyze` (`tse all <symbol>` for JSON, `--without book,statistics,breadth` to skip a section); Codal is a separate opt-in tool, `tse.codal`; the breadth is the exchange's own per-instrument rows for the newest published session (advancers/decliners/unchanged, median/average move, and the analysed symbol's percentile) with the 15-symbol large-cap proxy only as a fallback, and the statistics are the 3/12-month averages of value, volume and trade count plus the last session's VWAP with and without حجم مبنا, company value/rank and the 3-month per-capita real/legal buy/sell figures; dates and timestamps are Jalali (Shamsi), e.g. `1405/07/26 14:45:26`; `tse.find` screens the market, `tse.snapshot` stores fetches as `.stock` files (named `<JalaliYYYYMMDD>_<symbol>_<ISIN>.stock`), and `tse snapshot`/`tse markdown` read one back (metadata header + the rendered Markdown a live fetch would produce); identifiers are resolved through `tse.resolve` (finglish, fuzzy, composite `فولاد-IRO1FOLD0001` tokens, cached index)
- `tse.intraday` — intraday (per-minute) OHLCV bars for one instrument over one session or a range (`--days N`, capped at 30; `--date YYYY/MM/DD`; `--from`/`--to`), the live session counting as the most recent. A session is rebuilt from the per-trade tape (`Trade/GetTradeHistory`, or `Trade/GetTrade` for the live one; canceled rows dropped, rows deduplicated by trade number, trades sorted by time then number) and aggregated locally, with TSETMC's native 2-minute `Trade/GetTradeIntraDay` bars only as a live fallback (`source: live`). Consecutive identical-OHLC bars collapse to one `from`..`to` row, but only once a run exceeds `--collapse-threshold` (default 120 rows) so small/partial days keep every minute (`--collapse auto|on|off`, `--no-collapse` = `off`), and collapsed rows carry a `bars` column with the merged bar count. `--interval auto` (default) coarsens 1→2→3→5→6→10→15→30→60 minutes to fit `--max-rows` (default 2000), reporting the pick. The live session also prints the real-time `ClosingPriceInfo` quote (last price, running trades/volume, day range, running قیمت پایانی) and how far the CDN-cached `GetTrade` tape trails it. Every bar carries `vwap_rial` (its own volume-weighted average price from the tape; empty for the native 2-minute fallback, which has no turnover), and every completed session an `Official:` line from TSETMC's daily row — قیمت پایانی (`pClosing`, the day's VWAP capped by حجم مبنا) and its timestamp, last trade and change vs the previous close, first/range, trade/volume/value totals. Each session also carries its daily حقیقی/حقوقی breakdown in shares, rial value and trader counts, and the output states what TSETMC does not publish at all (per-minute حقیقی/حقوقی, closing-auction detail, per-instrument NAV history); the same tape additionally yields each session's `Session:` line (high/low with their times, the close's location in the day's range, the share of volume at or above the tape VWAP, the gap against the previous close), a `Structure:` line (the 5/15/30-minute opening ranges and the market-profile value area — POC and the 70% band) and the largest prints by rial value, while today's static price limits are printed in the header with the live price's distance from them; `--depth` adds the order book to every bar (best bid/ask sizes, spread, cumulative 5-level depth, imbalance) and `--depth-ladder` the whole 5-level ladder per row boundary with running cumulative depth, both sampled at each row's span end from TSETMC's per-level `BestLimits/{insCode}/{date}` stream (5 levels only, published after the close, ~two months back, ~440 KB gzipped per busy day) — the live session gets only its current `BestLimits/{insCode}` book, the 09:00 row is the opening-auction book and post-12:30 updates are dropped. An extras registry adds the surrounding context, each item individually selectable with `--with NAME[,NAME…]`/`--without NAME[,NAME…]` (`all` accepted)/`--only NAME[,NAME…]` and listed by `--extras`: `book` (on) prints two summary lines per session, the opening auction sampled at the first bar's end and the close at the last trade, with best bid/ask sizes, exchange order counts (a saturated count prints as `>=9,999`), spread, 5-level depth and imbalance; `orders` (on) and `opening` (on) control those counts and the auction line; `stats` (on) adds a `Context:` line with the 3-month average volume/trades/real buyers and company value beside the latest published session; `index` (auto, live sessions only) adds a `Market:` line from the live market overview (TEDPIX and equal-weighted change, market totals, state); `breadth` (auto, up to five published sessions at ~175 KB each) adds a per-session `Breadth (date):` line from the whole market's daily rows; `flow` (off) adds `buy_initiated_shares`/`sell_initiated_shares`/`net_shares`/`cum_net_shares`/`buy_pct` columns and a `Flow (estimated):` line, classifying each trade against the best bid/ask at its moment (at/above the ask = buyer-initiated, at/below the bid = seller-initiated, inside the spread to the side of the midpoint, the remainder reported as unclassified — `--flow` is the shorthand and implies the book). A source that cannot answer is skipped with a printed reason and recorded in the JSON `extras` provenance; a partial `BestLimits` stream (the endpoint's CDN edges can disagree while a day is still being published) is refetched on a fresh connection and refused with a note if it still does not span the session; `--ticks` prints the raw tape, `--profile` a price-level profile, `--json` JSON. Prices in rial, volume in shares, Jalali dates and `HH:MM` times; the CDN's gzip keeps a busy day ~0.5 MB on the wire; same identifier forms as `tse`; no cache
- `tse.resolve` — resolve Persian / finglish / fuzzy instrument names to TSETMC identifiers (symbol, ISIN, insCode, market/board) and cache the active-instrument index (`${XDG_CACHE_HOME:-~/.cache}/tse/instruments.json`, one week, `--refresh`); exact → finglish (`foolad`, `khodro`, phonetic `mobin` via `bin/finglish`) → fuzzy (`rapidfuzz`/`difflib`) with market-tier ranking so duplicated symbols pick the main-market listing (`فنفت`), composite `فولاد-IRO1FOLD0001` tokens accepted (`--complete` emits `finglish-ISIN` for Latin input and completes a partial ISIN); all `tse*` tools resolve through it
- `tse.codal` — Codal.ir client and the only Codal route (renamed from `codal`; `tse.codal search/statements/snapshot <symbol>`, plus `tse.codal cache path|list|clear`); resolves identifiers through `tse.resolve`, and `snapshot --markdown` renders the dataset used by `prompt tse.codal` (symbol header, Codal block, derived ratios). Solves search.codal.ir's rate-limit DDoS captcha with `tesseract` and keeps the cookie session that API requires, then extracts statement tables from `www.codal.ir` report pages. Codal resets connections (errno 104) and tarpits at random, so every request (captcha and report pages included) retries with jittered backoff inside an attempt/deadline budget (`CODAL_RETRIES`/`CODAL_TIMEOUT`/`CODAL_DEADLINE`) on a fresh socket, and successful artifacts are cached in `${XDG_CACHE_HOME:-~/.cache}/tse/codal`: fresh for `CODAL_MAX_AGE` (6h, `--max-age`), refetched when older, but still used as a fallback when the live fetch fails — cached output carries a `cache` note with the Jalali fetch time and the live error, and the Markdown prints it above the Codal block. `--refresh` forces live, `--cache-only` never goes online

## Gotchas

- `bin/` scripts have varying external dependencies — always check `--help` or header comments
- `prompt` auto-copies output to the clipboard; a prompt opts out by setting `r.no_clipboard`
- `prompt-compiler` needs Python 3 and shells out to `prompt list --names` for autocomplete
- `spp` needs `clang` and reads `.clang`/`.clangd` from the git root
- Codal fetches (`tse.codal`, used by `prompt tse.codal`) solve search.codal.ir's rate-limit captcha with `tesseract` (English traineddata); without it they fail with an install hint, and the search API needs its cookie session or it returns zero rows silently. Codal also resets connections (errno 104) intermittently — that is retried, not fatal — and the cache under `${XDG_CACHE_HOME:-~/.cache}/tse/codal` serves Codal data for 6h (`CODAL_MAX_AGE`) or as a fallback, marking it with its fetch time. `tse` itself no longer fetches Codal.
- `pods/stack start` sets `net.ipv4.ip_unprivileged_port_start=80` via sudo
- Firewall scripts need root and use nftables
- `transfer` service (transfer.sh) is currently down
