## [Unreleased]


### Added

- `bin/tse` history: every daily row now carries the historical حقیقی/حقوقی breakdown from `ClientType/GetClientTypeHistory` (the API behind tsetmc.com's `/History/<insCode>/<date>` page) — `individual_buy_shares`, `individual_sell_shares`, `legal_buy_shares`, `legal_sell_shares`, `legal_net_shares`, `individual_buyers`, `individual_sellers`, `legal_buyers`, `legal_sellers` — joined by date alongside price/volume/trade count in the CSV table, `tse history --json`/`--unadjusted` and `tse all --markdown`. The client-type series starts 2018-11-26 and a few later sessions are missing upstream, so those cells stay empty (missing = unknown, not zero); non-trading days also have no record. A failed client-type fetch no longer fails the price table, it is reported under `errors.client_type_history`
- `bin/tse` `snapshot FILE` and `markdown FILE` subcommands — print a `.stock` snapshot's 4-line metadata header, and render it to the same Markdown a live `tse all --markdown` fetch produces (CSV history, compact sections, `Instrument:` header). `prompt stock` (both `prompts-shell/stock.sh` and the C++ port) builds snapshot context through them, so a cached snapshot and a live fetch share one renderer
- `process::command` — fluent subprocess builder (fork/exec, `stderr_mode` inherited/captured/`2>&1`, timeout, env) plus `run_script()` for `/bin/bash -c`; the dead `run_pipeline()`/`run_async()` wrappers are gone
- `prompt::text` string utilities (`core/strings.hpp`), `embed_file_block()`, `warn_missing_file()`, `help_text()` — the repeated file-embedding, warning and help-capture patterns every prompt used to open-code
- `prompts/tests/test_errors.cpp` — the `prompt_error` exception surface (exit codes, partial stdout, clipboard opt-out, stdin-spent flag) that replaced the success-return struct
- `prompts/` — native C++ prompt dispatcher with **all prompts implemented natively**: no runtime dependency on the `prompts-shell/` directory (no scanning/reading/executing of prompt scripts; `new` embeds static snapshots instead). The native dispatcher is authoritative; the bash reference is kept for historical reference only and the old parity harness is no longer a gate (deliberate divergences: the redaction legend, the native-only `tse`/`tse.rigor`, and now `--num` plus the standardised help text)
- Native ports for the remaining prompt families: text/analysis (`api`, `explain`, `debug`, `diagram`, `metadata`, …), git (`git`, `git.diff`, `git-dirty`, `git.files`, `git.worktree.*`, `repo`, `verify`), tool wrappers (`clang-tidy`, `cmake`, `gdb`, `cppman`, `ci`, `docker`, `gh.issue`, `paths`, …), stdin/translate (`english`, `farsi`, `stdin`, `tweets`, `symbols`, `summarize`, `yt`), complex (`agents`, `ai-said`, `ask-for-help`, `skill`, `opportunities`, `fs8.mod`, `fs8.test`), plus the shared dispatch/chaining/pipeline/clipboard/sanitize SDK
- `prompt::fs::bin_tool` — locates repo `bin/` utilities (exe dir → git root → cwd walk → PATH) without going through the prompt scripts
- `prompts/new` is now native: `prompt new` asks an AI to write a `prompts/src/prompts/<name>.cpp` (self-registering, `prompt_context`-based, throwing on failure) instead of a bash script, and embeds the SDK headers plus the `fix` prompt as its reference. This is the one prompt that deliberately diverges from `prompts-shell/new.sh`
- `prompts/cmake/embed-assets.cmake` — bakes the `new` reference sources into the binary at build time (`${CMAKE_BINARY_DIR}/generated/prompt_assets.hpp`) instead of the checked-in `src/prompts/prompt_assets.hpp`, so the snapshots can't drift from the SDK
- `prompt tse` — the raw TSETMC dataset for one instrument (live fetch or `.stock` snapshots) with **no analysis instructions**, for piping or chaining into your own workflow (`prompt tse فولاد .note "compare with فخوز"`). Same flags, identifier forms, clipboard fallback and snapshot handling as `stock`, which is now `tse` + the institutional-analyst instructions; the two share their data-collection code in `prompts/src/prompts/tse_data.hpp`
- `prompt tse.rigor` — a market/TSE analysis and backtest honesty checklist (compute ratios from a table instead of prose, no look-ahead bias, require baseline/median/win-loss/expectancy statistics, label "reported, not independently verified" numbers, give left-tail risk the same prominence as mean returns); standalone or chained (`prompt tse فولاد .tse.rigor`). Both `tse` and `tse.rigor` are native-only — the bash reference has no counterpart, so the parity harness filters them from the `list --names` catalog cases with its `#native-only` directive
- `prompt tse.times` — the pre-open and continuous-trading session times for every Tehran Stock Exchange (TSE) and Iran Fara Bourse (IFB) instrument category (stocks & rights, equity/balanced ETFs, TSE and IFB fixed income, agri commodities, gold funds/coins, glass and cement certificates, energy funds/energy carriers/energy savings, REITs, housing facility, fund-of-funds, fixed income funds) plus the Sat–Wed trading week. A native-only reference prompt, standalone or chained (`prompt tse فولاد .tse.times`)
- `prompts/` redaction legend: when the sanitizer rewrites personal data (`HOME`, `USER`, `HOSTNAME`, `IP_ADDRESS`, `MAC_ADDRESS`, `EMAIL_ADDRESS`, `PHONE_NUMBER`, `SSN`), the dispatcher prepends one line naming those placeholders to the output and clipboard (`sanitize::kRedactionLegend`), so a model reading the prompt knows they are redactions, not the original text. `sanitize::sanitize()` now reports `{text, redacted}`, and `tests/test_sanitize.cpp` covers the flag and the legend
- `prompt --num` / `--numbered` on every file-embedding prompt (`files`, `fix`, `review`, `git.files`, `git-diff`, `skill`, …): prefixes each embedded line with a right-aligned `N | ` number, relative to the kept content (so `--head N` numbers `1..N`). Off by default; diffs and command output stay unnumbered. Backed by the new `file_options_or_throw()` (the file prompts' whole CLI), `is_number_flag()`/`kNumberFlags`, `number_lines()`, and the `file_usage_help()`/`file_options_help()` helpers that now generate every file prompt's `Usage:` lines and shared `--head`/`--num` Options block instead of re-typing them
- `prompts/src/sdk/args.hpp` helpers for the boilerplate every prompt repeated: `head_lines_or_throw()` (the `--head` parse plus the `throw usage_error{…}` preamble), `file_options_or_throw()` (`--head` + `--num`), `positional_args()` (args minus the `--head <value>` pair and the `--num`/`--numbered` flags) and `collect_file_args()` (splits FILE arguments into the regular files to embed and the missing ones to warn about)
- `prompts/tests/test_embed.cpp` — `number_lines`, `file_options_or_throw`, the flag filtering and the shared help helpers, plus a ctest smoke that runs the built binary with `files --num`
- `prompts/AGENTS.md` — a subtree guide for working on the native dispatcher (build/test/lint commands, the prompt contract, the SDK helpers and the output-bytes policy)
- `bin/browser.find`, `bin/cookies` and `bin/browser.storage` — shared browser-profile discovery plus credential/web-storage extraction, Chromium-family first then Firefox-family: `browser.find` lists installed browsers, their profiles, running instances and the system default; `cookies` extracts cookies and saved logins (Chromium AES-128-CBC values via the login keyring, Firefox `logins.db` or `logins.json`+`key4.db`) to stdout, pointing at `browser.storage` on a miss (`--no-hint` to disable); `browser.storage` reads per-origin `localStorage`/`sessionStorage` (Firefox `ls/data.sqlite` with in-process Snappy, Chromium's LevelDB through a built-in read-only SST/WAL parser)
- `bin/ai.chatgpt`, `bin/ai.grok` and `bin/ai.dseek` — ask ChatGPT, Grok and DeepSeek from the shell by replaying each site's own web API with the browser's signed-in session: no API key, no official API and no browser at run time. One shared engine (`bin/ai/`: providers, normalised `thinking`/`text`/`tool_call`/`usage`/`done`/`error` events, a renderer and a CLI) adapts each transport — ChatGPT's `f/conversation` conduit behind the sentinel gate (requirements token, `zvt` proof-of-work and the turnstile VM, ported in `bin/ai/sentinel.py`), Grok's `wss://grok.com/ws/mgw/` WebSocket (`session.create`/`response.create`) and DeepSeek's `DeepSeekHashV1` proof-of-work plus fragment-patch stream. Prompts come from arguments or stdin; answers stream as Markdown on a TTY (reasoning dimmed, tool calls display-only), piped output keeps stdout clean with reasoning/tools on stderr, and `--json` emits one event per line; `--model`, `--system`, `--show-thinking`/`--no-thinking`, `--raw`, `--copy`, `--timeout` and the `browser.session` selectors (`--browser`/`--profile`/`--family`/`--open-only`/`--exact`, `--print-session`) are shared
- `bin/browser.session` — compose a site's authenticated HTTP session (cookies via `cookies`, `localStorage`/`sessionStorage` via `browser.storage`, and a matching `User-Agent` via `browser.find`) as `json`/`cookie`/`header`, so a script can replay a site's own API calls without a browser; the `ai.*` commands use it to sign in
- `bin/browser.record` — a development-only recorder (Playwright + the system browser) that saves a page's XHR/fetch/SSE traffic with headers, bodies, full `text/event-stream` bodies and WebSocket frames, optionally typing and sending a prompt; used to derive the `ai.*` adapters' endpoints and payloads

### Changed

- Layout: the native C++ dispatcher moved from `cpp_prompt/` to **`prompts/`** and is now the installed `prompt` command; the original bash implementation moved to **`prompts-shell/`** (dispatcher `prompts-shell/prompt.sh` plus `_common.sh` and the `*.sh` prompts), where it stays runnable as a historical reference. `cmake --install prompts/build --prefix "$HOME/cmd" --component prompt` drops the binary at `bin/prompt` (gitignored), so `prompt` on `PATH` is the native dispatcher; the native `--help` no longer claims to scan `$XDG_CONFIG_DIRS/prompts` or run `.sh`/`.txt`/`.md` files
- `prompts/` structure: a prompt is one file that implements and registers itself — `static void execute_<name>(prompt_context&)` writes `ctx.out`/`ctx.err` and **throws** on failure (`usage_error`/`soft_error`/`prompt_error` in `sdk/errors.hpp`); the dispatcher catches them once in `main.cpp`'s chain loop. The `prompt_output` return struct, the 76 per-prompt header pairs, the umbrella `prompts/prompts.hpp` and the central `prompt_entry.cpp`/`register_batch_*.cpp` registrars are all gone; each `src/prompts/<name>.cpp` ends with a single `prompt::register_prompt(...)` call at static-init time (hence `prompt_lib` is an OBJECT library, so the registrars aren't dropped)
- Subprocesses run through fork/exec instead of `popen` + shell-quoting: argv reaches the child verbatim, child stderr can be captured or merged, and timeouts are enforced
- Repeated `output += "literal" + x + "literal"` sites (143) converted to `std::format`; lying `noexcept` qualifiers removed (they aborted on `std::stoull`/`std::regex` failures) and the numeric parsing hardened
- `prompts/` prompt sources tidied: contiguous `output += "…\n"` prologues are single raw string literals, adjacent `std::format` calls are merged, the `prompt_context` service wrappers became free functions taking the context, and `infer_lang` returns `std::string_view`
- `stock`/`intraday` fetch through `python3 bin/tse … --markdown` exactly like `stock.sh` (the tool's stderr is inherited); skill frontmatter parsing and the KDE clipboard path are C++/`qdbus` — `prompts` no longer embeds or links libpython (`src/core/python.cpp`, `src/tse/tse_python.cpp` and the LeakSanitizer suppressions deleted)
- Chain semantics in both dispatchers corrected and documented in `AGENTS.md`: chained prompts share the ORIGINAL piped stdin (nobody feeds a prompt's output into the next); a prompt that reads stdin (`read_stdin`/`embed_stdin`) spends the pipe for later prompts, reported natively via `prompt_context::stdin_consumed` (or `prompt_error::stdin_consumed()`)
- `bin/prompt auto` stock-identifier extraction bug fixed in `prompts-shell/auto.sh`

### Removed

- Embedded CPython from `prompts` — the binary now shells out to the repo's shell/Python tooling the way the bash prompts do
- `prompts/src/legacy/` and `include/prompt/legacy/` (the bash-script fallback runner) — `prompts` no longer knows about or accesses the `prompts-shell/` directory at all
- `prompt_descriptor::script`, `set_sort_file()` and `set_help_texts()` from the registry; `prompt_search_dirs()`/`find_prompt_file()`/`detect_file_type()` from `prompt::fs`
- The C++ `.stock` snapshot renderer (`prompts/src/tse/`, including `tse_markdown.cpp`) — snapshots now render through `bin/tse markdown`, so live fetches and cached snapshots share the one implementation in `bin/tse` (the C++ port had drifted from its column set)

### Fixed

- `prompt ask-for-help` copies its output to the clipboard again: the native port set `no_clipboard` unconditionally, while the bash reference only suppresses the copy of the *inner* `list.sh` catalog it embeds (`PROMPT_NO_CLIPBOARD_FILE=/dev/null`) — `list`/`list-prompts` remain the only prompts that opt out
- `fs::bin_tool` now finds repo tools when the binary is **installed** in `bin/`: it looked in `exe_dir/bin/<tool>` (`bin/bin/tse`) instead of `exe_dir/<tool>`, so `prompt stock` (and every tool-invoking prompt) failed outside the build tree with `python3: can't open file '.../tse'` — the miss also fell back to a bare name, which callers then opened relative to the cwd. The `$PATH` fallback now resolves to an absolute path, and `tests/test_fs.cpp` locks the installed/build/git-root/PATH layouts
- Empty-but-piped stdin handling: `note` (and other stdin-reading prompts) print the same blank embed block as `embed_stdin || true` when the pipe is empty, keeping chained output byte-identical to bash
- `resolve_input_file` matches the bash implementation (cwd → git root → `git ls-files | fzf -f`)
- `prompt stock` in the C++ dispatcher honours `--head`: it was parsed but never applied, so `prompt stock --head N <snapshot>` printed the full rendered snapshot instead of the capped one
- Debug-build `-Wall -Wextra -Wshadow` warnings from `process.cpp` (unused `quote_for`) and `skill.cpp` (a shadowed loop variable) cleared
- `--head 0` audited across every prompt: context trimming now mirrors `sed -n "1,0p"` (keep line 1) via `trim_context`/`trim_context_nl`, while the paths that really run `head -n N` (`run`, `clang-tidy`) keep nothing — matching bash byte-for-byte (`std::optional<std::size_t>` distinguishes "unset" from a real `0` cap)
- `prompt paths` consumed `--context`/`--head` values as paths (the flag was read but its operand was not) — a file's context and head cap are now applied and the operand no longer leaks into the path list
- `prompt intraday --head N` was parsed but never applied (the cap was silently dropped); `--head` is now validated like `parse_arguments` and honoured through `trim_context`
- `prompt list`/`list-prompts` rejected `--head N` (bash strips it via `init_prompt`→`parse_arguments`); both now accept and validate it
- `prompt note --head` with no value treated `--head` as note text; it now fails with `Missing value for --head` (exit 2) like `note.sh`
- `prompt clang-tidy --head N` kept a trailing blank line bash drops (`head -n N` inside `$(...)` strips it)
- `prompt skill <unknown>` no longer leaks `bin/ai-find-skills`'s `# full JSON: <tmpfile>` stderr note (the bash download path redirects it to `/dev/null`)
