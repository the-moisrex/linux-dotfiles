## [Unreleased]


### Added

- **Prompt files (`*.prompt`)** — the chain shorthand can live in a file: `prompt debug.prompt` runs the file's tokens as if they had been typed after `prompt`, and any argument token ending in `.prompt` that names a readable file is replaced, in place, by the tokens it holds, so `prompt .note "context" debug.prompt .length short` works too. A file is split on spaces and newlines, `#` at the start of a token comments out the rest of its line, `"..."` (with `\"`/`\\` escapes) and `'...'` quote, and nothing else is expanded — no `$VAR`, no globbing, no command substitution. A name is looked up next to the file that named it (the current directory at the top level), then `<git-root>/.prompt/`, then `$XDG_CONFIG_HOME/prompt/prompts`; files may include other files (8 levels deep, cycles rejected), a leading `prompt` token is dropped, and every token after `--` is copied verbatim, so `.exec -- command x.prompt` is never rewritten. `prompt --no-prompt-files …` turns the pass off, and an unresolved `*.prompt` token is an error only in the first position (elsewhere the prompt owning the argument keeps its own warning, e.g. `.files missing.prompt`). The pre-pass runs before chain parsing (`prompts/src/sdk/prompt_file.cpp`), so sinks, `.each` bodies, the clipboard and the history store only ever see an ordinary argv — the history records the effective tokens. Tests: `prompts/tests/test_prompt_file.cpp` (tokenizer, inlining, nesting, cycle, depth, lookup order, `--`, `--no-prompt-files`) plus the `prompt_file_run`/`prompt_file_missing` ctests over `tests/fixtures/hello.prompt`.

- **Function steps (`prompt .func NAME(params) STEPS… .end`, called as `.name`)** — the third kind of chain step, next to prompts and sinks: a named, parameterized chain template the user defines and invokes exactly like a prompt. The signature is a single token (`NAME` or `NAME(p, p=default)`, no spaces inside the parens); a call fills the declared params by position or with `--name value`/`--name=value`, `{name}` in the body is a value, `{@}` (as a whole token) the positionals past the declared ones, `{0}` the function name and `{N}` the Nth argument, and a `{field}` that is not a parameter is left alone so a function composes with `.each`. Definitions live in the command, in a `*.prompt` file, or in `funcs` files (`<git-root>/.prompt/funcs` and `$XDG_CONFIG_HOME/prompt/funcs`, project over user; `$PROMPT_FUNCS` replaces the list and an empty value disables them). A function may not shadow a built-in prompt or sink, and a bad definition is a hard error (exit 2). Expansion runs in `main.cpp` after the `*.prompt` pass and before `parse_chain` (`prompts/src/sdk/function.cpp`), so sinks, `.each` bodies and the history store only ever see an ordinary argv. Tests: `prompts/tests/test_function.cpp` (definition/call, params/defaults/named flags/`{@}`/`{0}`/`{N}`, nesting, `.each`-body and `--` preservation, every error case, `funcs`-file loading and override) plus the `function_inline`/`function_params`/`function_shadow` ctests.

- **Shell completion moved into the dispatcher (`prompt --complete-line`)** — the candidates a shell offers are now computed in C++ instead of by the fish script, and `shell/completions.fish` shrank to one function and two `complete` lines that forward the line (`prompt --complete-line "$current" $tokens[2..-1]`, with `-f` at the name position and at a `.`/`-` step boundary, so fish's own path completion still applies among a prompt's arguments). The new line mode classifies the position itself (`prompts/src/sdk/line_completion.cpp`): at the head it offers the dispatcher's flags, every prompt name in all three spellings (`name`, `.name`, `-name`, described by each prompt's own summary) and the `*.prompt` files that can be inlined there — from the current directory, `<git-root>/.prompt/` and `$XDG_CONFIG_HOME/prompt/prompts`, nearest first, each candidate naming its source, a name two sources share emitted once, and a token containing `/` listing that directory instead (its `*.prompt` files plus its subdirectories, so the user can descend); a `.name`/`-name` token completes as the next step, anything else as an argument of the open prompt, and a `.exec --` tail or an open `.each` body is left to the shell. Prompt files previously came from a `path filter -f "*.prompt"` line that never matched anything (`path filter` does not expand globs and the pattern was quoted), so completing a `*.prompt` file did not work at all. The single-prompt `prompt <name> --complete <prefix> [args...]` form is unchanged, and both forms now render through the same `write_prompt_candidates` (help-derived flags plus the prompt's own `complete_fn`), so a prompt answers identically either way. Tests: `prompts/tests/test_completion.cpp` (the three spellings and prefix filtering, the shared renderer, the three prompt-file sources with dedup and source descriptions, and every position the line mode classifies) plus the `complete_line_head`/`complete_line_step`/`complete_line_values`/`complete_line_prompt_file` ctests.

- **Function completion in the line mode** — `.func` is a keyword the completion offers, and the functions visible at that point are offered alongside the prompts in all three spellings. `line_completion` runs the line through the `*.prompt` pass first (`expand_prompt_file_tokens`), so a definition in an inlined file is found, then merges the global `funcs` files (`function_table::all`) with the inline `.func … .end` blocks (`collect_inline_functions`); `.func` is offered at the top level, `.end` inside a `.func` body (which completes as a chain), and a function call opens a step whose boundary still completes names. `write_step_names` renders prompts and functions in one merged locale-aware order. Tests: the `complete_line_func`/`complete_line_inline_func` ctests plus the function cases in `test_completion.cpp` and the `collect_inline_functions` cases in `test_function.cpp`.

- `bin/accounts` — a cross-browser account manager: an *account* is a named identity for one site (`x.com/work`, `x.com/personal`), a *profile* is one browser profile written `browser/profile` (`firefox/default-3`), and the tool copies the session state — cookies **and** `localStorage` — between them, so one identity moves between Brave, Chromium and Firefox and two identities share one browser. The pipeline is `profile --add--> account --install--> profile`: `add` captures what a profile already has or logs in for you when none does (throwaway `--user-data-dir`, so a new identity cannot inherit the old one's state; `--login` forces it, `--at` names the profile to log in inside, `--keep-session` skips the clearing), `install` is an exact replacement (`--merge` additive, `--dedicated` uses an `accounts-<label>` profile), `open` installs and launches the browser, and `logout` strips a site's state again. `list`, `show [--reveal]`, `profiles`, `diff` (dry comparison), `forget`, `export`/`import`, `new-profile` (create a dedicated `accounts-<label>` profile, registered in Firefox's `profiles.ini` and visible in both pickers) and `undo` complete the set. `--at BROWSER[/PROFILE]` names a profile (a bare browser means its default, a bare name is matched against profile names); without it the profile is auto-detected: the account's recorded profile, then the only profile that actually holds the site's cookies/`localStorage` (counted without decrypting anything), then an `fzf` picker (numbered list without it) on a terminal — `--pick` forces it and reads the answer from stdin, `--no-pick` and `--json` turn it into an error that lists the candidates with their cookie/key counts. Bundles live under `${XDG_DATA_HOME:-~/.local/share}/accounts` (`0700`/`0600`, `ACCOUNTS_DIR` override, `index.json` + `sites/<site>/<label>/`), stored *decrypted* so a bundle crosses browser families; Chromium values are re-encrypted with the target profile's key only when that key is **verified** against a stored cookie (an unverified libsecret key makes Chromium silently drop the cookie on next start), otherwise written to the plaintext `value` column, which Chromium reads too. Writes require the profile to be closed (`browser.find` plus an independent `/proc/*/fd` scan; `--close` SIGTERMs it first), are backed up per profile (rotated, last 10) for `undo`, and `--dry-run` prints the exact row/key operations. Storage backends are the ones `cookies`/`browser.storage` already read: Chromium cookies in `Cookies`, Chromium `localStorage` by appending a hand-built LevelDB write-ahead-log batch to `Local Storage/leveldb/*.log` (CRC32C, fragmented records, sequence read from the MANIFEST — no `plyvel`), Firefox's `cookies.sqlite` and per-origin `storage/<default|permanent>/<origin>/ls/data.sqlite` (with `database.usage` and `ls/usage` kept in step); a fresh profile has no origin store yet, so the command warns and applies cookies only. Firefox's `originAttributes` (container / `userContextId`) round-trips, `sameSite` is mapped between the two families, and saved passwords are deliberately not moved.
- `bin/md.extract` — pull blocks out of Markdown (stdin or files): fenced code (` ``` `/`~~~`, blockquoted and list-indented fences included), sections (`--kind section --heading X`, subsections by default), GFM tables and frontmatter. Each block is parsed with its context — the enclosing heading path plus the prose paragraph before and after — so "the csv block whose intro says X" is two filters: `--lang csv --before "monthly totals"`. Selectors are independent and AND-ed (`--kind`, `--lang`, `--heading`, `--under`, `--before`, `--after`, `--title`, `--grep`, `--indented`, case-insensitive regex with `-F/--literal`), `--lang` compares families (`c++`/`cxx`/`hpp` → `cpp`, `bash`/`console` → `sh`, `patch` → `diff`, `py` → `python`; `any` = untagged, `*` = all) and `--guess` sniffs untagged bodies. `--list` numbers the rows of the current selection, so `-n N` (`2-5`, `1,4`, `-1`, `--first`/`--last`) re-selects a row, `--pick` opens fzf and `--one` requires a single match. Output is the body alone (pipe into `git apply`/`jq`); `--fence` re-emits the original fence, `--with-heading`/`--with-intro` add provenance, `--json`/`--jsonl` emit full records, and `-o FILE`/`--out-dir DIR` (named from `title=`, the heading or `<lang>-<index>`, with `--ext`, `--force`, `--dry-run`) write matches to disk. Exit status is grep-like (`0` matched, `1` nothing, `2` usage error), unclosed fences warn on stderr without failing. The selector grammar `kind[:qualifier][@N]` (`table`, `code`, `section`, `command`, `frontmatter`, `any`, `auto`, `none`, or a bare heading) is shared with the native agentic prompts: `--select SPEC` extracts one shape, `--items SPEC` emits a JSON item array (table rows keyed by column, or one item per block), `--contract SPEC` prints the matching AI response instruction, `--kinds` lists the grammar, and the `command` kind views a code block as the command on its first non-comment line (`command:prompt`).
- **Agentic prompt chains** — `.expect` states a response contract, `.extract` selects it out of the answer, `.exec` runs the resulting command, and `.each … .end` loops a normal chain body over the selected items. `bin/md.extract` owns the grammar/contracts (`--select`/`--items`/`--contract`) and the native prompts only call it. `.expect SELECTOR` appends the contract to the chain context and publishes `keys::expect`, which `.extract`/`.exec`/`.each` reuse before falling back to `auto`; `.delegate` publishes `command:prompt` itself. `.extract` is a sink that replaces the context with the selection (`--list` inventories on stderr and keeps it, `--json`/`--pick` pass through). `.exec` extracts a command from the context (or takes `-- COMMAND…`) and replaces the context with its output; a context that is exactly one `prompt …` line runs that chain directly, which makes `.extract .exec` the two-stage delegate flow. It runs no shell (direct arguments verbatim, one whitespace-containing token as a quoted command line, compound `| > && $(` refused) and asks `sdk/policy.*` before running: built-ins (`tse*`/`md.extract` allow, `sudo`/`su`/`dd`/`mkfs*`/shutdown programs deny, everything else ask), `~/.config/prompt/policy`, `<git-root>/.prompt/policy`, and `PROMPT_POLICY_ALLOW`/`PROMPT_POLICY_DENY`; more specific rules win, then the higher source, deny wins ties, and `--yes` turns asks into allows but never overrides a deny. A generated `prompt …` chain is shown whole and approved through `require_chain`, and a `prompt` command passed as arguments needs `--` so the outer chain does not split it. `.each [SELECTOR] [flags] BODY .end` keeps the raw body at parse time (`takes_body`), substitutes `{field}`/`{item}`/`{body}`/`{index}`/`{n}`/`{file}` into its tokens, and runs one child `prompt` per `md.extract --items` item in parallel (`-j`, default min(items, 8), `--limit`, `--stdin`, `--print`, `--list`, `--json`, `--no-header`, `--keep-files`, `--on-item-error stop|skip|keep`, `--timeout`, `--yes`). Bodies nest with `.end` depth counting (a missing/unexpected `.end` is a parse error, loops cap at depth 2), item data can never become a prompt name or `.end`, and a `{field}` `.exec` program is allowed but dynamic (the child's policy approves the resolved command). Children run with `PROMPT_INNER=1`/`PROMPT_INNER_DEPTH`/`PROMPT_INNER_ALLOW` (and `PROMPT_INNER_YES` with `--yes`), so the parent alone copies the clipboard and prints one redaction legend; `.each` pre-approves the static `.exec` programs in the body once, while dynamic commands ask in the child.
- **Multi-value extraction and AI-named saves** — `.expect`/`.extract` now take several `[NAME=]SELECTOR` entries instead of one selector. Exactly one entry is **unnamed** (the primary: it replaces the context, and `.exec`/`.each` use it), and every **named** entry is run `md.extract --select --one` and published as that fact, so one answer can yield both an artifact and its name. The `field:LABEL` selector (`field:filename`) extracts a `LABEL: value` line, and `md.extract --contract` became repeatable (one entry keeps the old text, several emit one combined envelope). `.save` declares `keys::save_wants_name` when it is given **no** explicit `FILE`/`DIR`, which makes a preceding `.delegate` add a "name the file" instruction and publish the plan `command:prompt` + `save.stem=field:filename`; the model's `filename:` then becomes the saved file's name (`prompt .expect command:prompt save.stem=field:filename .ai.dseek .extract .save` writes `<name>.prompt`), while an explicit save target suppresses the request. An explicit `.expect` after `.delegate` overwrites the plan (and loses the filename binding). Tests: `prompts/tests/test_md_extract.py` (the `field` selector and the combined contract) plus the `agent_expect_plan`/`agent_extract_field`/`agent_extract_bind` ctests.
- **A read-only `view` and a write-only `result` replace the mutable `prompt_context`.** A prompt is now `static void execute_<name>(view const& v, result& r)`: the `view` carries everything a segment may *read* (`v.name`, `v.args`, `v.in.text()`, `v.env.git_root`/`v.env.exe_path`, `v.text` — the chain barrier a sink reads — `v.prior` facts and `v.stream`), and the `result` carries everything it may *produce* (`r.out`, `r.err`, `r.stderr_buffer`, `r.published`, `r.no_clipboard`, `r.clear`, the streamed flags). Not one prompt mutates chain state, which is what lets independent segments run in forked parallel children; `prompt_context`, `clear_output`, `wait_for_prompts` and the fragile "copy the context and overwrite a field" composites are gone.
- **Facts: typed-ish communication without a framework.** `prompt::facts` is an ordered string→string store (values are length-prefixed on the wire, so any content survives), the only inter-prompt channel, with well-known keys in `namespace prompt::keys`. There are exactly two write points and two merge rules: **declarations** (`register_prompt`'s last argument, a `declare_fn(declaration&)`) run in the parent *before* any batch forks and keep the first writer, so parallel siblings agree on pre-derived identity; **artifacts** (`r.published`) are published by a finished segment and keep the last writer, i.e. the nearest successful preceding segment. No `std::variant`, no codec template, no precedence graph — the two rules are one line each in `main.cpp`. The `tse` family declares its instrument once (`prompt .tse foolad .tse.codal` and the reverse order both resolve `foolad`, and each `tse*` prompt publishes the resolved identity), so the clipboard is only consulted when nobody named a symbol. `.save`'s filename hint is simply the `keys::save_stem` fact, so the separate `chain_save_hint` plumbing disappeared.
- **One wire for the fork**: `sdk/wire.hpp`'s `segment_outcome` (stdout, stderr, the separate stderr buffer, published facts, the output flags, exit status) is encoded into one length-prefixed blob per child, and `drain_all()` reads every child pipe concurrently with `poll()` (closing every fd exactly once when the loop ends) instead of draining them one at a time, so a fast child no longer waits behind a slow sibling in a parallel batch. `hint_size`/`save_hint` and the hand-rolled per-field writes are gone.
- `prompts/tests/test_facts.cpp` — the fact store (get/set, both merge rules), the wire codec's round-trip and truncation handling, `segment_outcome` encode/decode, and `drain_all` on a fast and a slow child (the slow one writing past a pipe buffer).
- Parallel execution got cheaper and quieter: `sanitize::strip_osc` returns its input untouched when there is no `ESC` byte (the common case) instead of running the regex, `clean_privacy` compiles its patterns once per process rather than on every call, `fs::bin_tool` tests each candidate directory as it produces it (the common case finds the tool immediately and never walks the cwd), and `plan_chain`/`parse_chain` no longer cap a chain at 8 invocations/16 arguments.

- `bin/ai.debate` / `prompt .ai.debate` — two or more AIs verify each other's answers in a relay. The first provider answers the question; its answer goes to the next provider as `Another AI said:` together with a verification request; each participant keeps its **own** conversation, so later turns only carry the newest answer, and the ring runs for `--rounds N` (default 2) or until every AI's `VERDICT: AGREE` line agrees (`--until-agree`). The leading positionals are providers (`chatgpt`, `grok`, `deepseek`/`dseek`, `gap`, `kimi`), the rest is the question (or stdin); `--context last|all` (`--transcript`) picks the last answer or the labelled transcript for the chain context and clipboard, `-m PROVIDER=MODEL`/`-s`/`-f` configure each side, `--instruction`/`--no-instruction` replace the verification request, and `--print-prompt`/`--print-session`/`--list` are offline dry runs. Sessions load for every provider up front; a failed or empty turn stops the relay with the last complete answer in the hidden `--context-file` side channel the `.ai.debate` sink reads back (it forwards `--tty`/`--width`/`--height` like `.ai.*`). The relay reuses `bin/ai/cli.py`'s turn/streaming/renderer/context helpers (with a new `fields` tag on `--json` events), so the single-provider commands and the relay run the same path. A debate starts fresh chats by default; `-c/--continue` reopens each participant's chat from the last debate between the same provider set (state in `$XDG_STATE_HOME/ai/debate-<providers>.json`, written after every successful turn), and `--new` discards it.
- `bin/ai.lms` / `bin/ai.openai` (and the native `prompt .ai.lms` / `.ai.openai` sinks) — the same `ai.*` engine over an **OpenAI-compatible HTTP API** instead of a website session: `ai.lms` talks to a local **LM Studio** server (no key, no cloud) and `ai.openai` to `api.openai.com` (`$OPENAI_API_KEY`) or any compatible endpoint through `$OPENAI_BASE_URL` (OpenRouter, Groq, vLLM). One shared engine (`bin/ai/providers/openai_compat.py`) maps the `POST /v1/chat/completions` SSE stream onto the existing events (text, `reasoning_content`, tool calls, usage, done), so rendering, `--json`, `-s`, `-c`/`-i`, `--copy` and the sink semantics behave exactly as with the web providers. `ai.lms` finds its endpoint from `--base-url`, `$LMS_BASE_URL`, the cached one (`$XDG_STATE_HOME/ai/lms-endpoint.json`), a short probe of the usual local ports (`1234`, `1337`, `8080`, `8000`, `11434`) and finally `lms status`, then caches the winner; the model comes from `-m`/`$LMS_MODEL`/`$OPENAI_MODEL`, falling back for `ai.lms` to the first chat model the server reports through `/api/v0/models` (which also marks the loaded one and hides embedding models) while `ai.openai` requires an explicit model instead of guessing one. `--param KEY=VALUE` forwards arbitrary inference parameters (`temperature`, `max_tokens`, …), `--print-session` reports the endpoint, model and reachability as JSON, and `--list` shows the providers and their models. Neither has an upload endpoint, so `-f` inlines the file into the message (text as a fenced block headed `File: <name>`, images as `image_url` data URLs, other binary types refused) and `--prompt-file` fails with that remedy; both are stateless, so `-c`/`-i` replay the saved transcript as the request's `messages`. `bin/ai/net.py` now reads the *body* of a streaming error response (empty until read), so a failure keeps the server's own reason (`HTTP 500: …`) instead of the status line alone, and an `ApiError` raised mid-turn is reported as a normal provider error rather than escaping as a traceback. `ai.debate` accepts `lms`/`lmstudio` and `openai`/`oai` as participants (with `--base-url`/`--api-key`/`--param` for them, and no browser session loaded), and `ai.save` refuses the two keyless providers (its `openai → chatgpt` alias is gone). Tests: `prompts/tests/test_ai_lms.py` drives the engine against a threaded `http.server` stub (SSE mapping, discovery and caching, model defaulting, `--param` forwarding, inline attachments, `-c` replay, the `--prompt-file` refusal, missing-model/context-limit/connection error remedies), plus the `ai_lms_help`/`ai_openai_help` ctest smokes and `.ai.lms`/`.ai.openai` cases in `test_ai_sink.sh`.
- `prompt length` (chained as `.length`) — tells the AI how long (or short) its answer should be. A target is a number with an optional unit — words by default, or lines, sentences, paragraphs, characters and tokens — accepting `200`, `10 lines`, `--words 200`, compact suffixes (`200w`, `10l`, `3p`, `500c`, `300t`), thousands (`2k`) and number words (`a few sentences`, `a couple of paragraphs`), or a preset — length presets (`tiny`, `short`, `medium`, `long`) and shape presets (`one-liner`, `sentence`, `paragraph`, `bullets`, `title`, `tweet`, `sms`, `email`, `letter`, `blog`, `article`, `report`, `essay`, `abstract`, `outline`, `notes`, `caption`, `bio`, `commit`, `changelog`, `thread`, `tldr`) — with no target defaulting to `medium` (about one or two paragraphs). Targets are approximate by default (`about 200 words`); prefix with `=` or pass `--exact` for a hard target, and `--max`/`--min` only cap or only extend. Against a chain it is just another instruction segment (`prompt .fix src/main.cpp .length 200`), and it also works as the instruction a later `.ai.*` sink sends.
- `prompt .save [FILE|DIR]` — a passthrough chain sink that writes the accumulated context (the same sanitized, `--head`-trimmed text an AI sink receives) to disk and leaves it unchanged for later segments, so `prompt .files a.cpp .save review.md .ai.grok` saves the files and still sends them to Grok. With no target it derives a name from the nearest successful preceding prompt's `save_hint`: `tse-<symbol>.md` from the `tse` family, the snapshot stem for `.stock` input, or the first embedded file's stem from `.files`, falling back to `prompt-<timestamp>.md`. A target that is an existing directory, ends in `/`, or has no file extension is treated as a directory and created automatically; an existing non-directory or a name with an extension is the exact file, and `--dir`/`--file` override the heuristic. Hints are sanitized basenames, missing parent directories are created, and a dispatcher preflight creates and checks the destination for writability before any prompt runs (so a path component that is a file fails fast with `exists but is not a directory`). Existing files are refused unless `--force` is passed (`--allow-empty` writes an empty context). A successful silent sink is a chain no-op: it does not clear the context or a source-batch failure taint, and it adds no output separator.
- `prompt .clear` / `.flush` — context-reset chain sinks for running several independent sections in one invocation. `.clear` discards the accumulated context and everything a later sink would inherit (the filename hint, the redaction note, the barrier stderr and the source-batch failure taint) while keeping output already printed, the clipboard and the exit status, so `prompt ... .ai.grok .save one.md .clear ... .ai.grok .save two.md` behaves like two runs sharing one output stream; a leading `.clear` also drops unconsumed piped stdin. `.flush [FILE|DIR] [save options]` is exactly `.save` followed by `.clear` — same target rules, filename hints, `--force`/`--allow-empty`/`--dir`/`--file` and the same preflight — with the reset applied only after the write succeeds, so a refused or failed save leaves the context intact. The reset travels through `result::clear` (an output flag like `no_clipboard`), so the sink declares it and the dispatcher, which owns the accumulated state, applies it.
- `prompt .c.p` / `.c.c` — the clipboard as a chain step, matching the `bin/c.p`/`bin/c.c` shell names. `.clipboard` (with its short alias `.c.p`) stays a **source** that reads the clipboard into the context and keeps `--head N` capping the pasted text, counted from the first real line because the paste trims the clipboard's blank edges first (an optional `paste` subcommand is accepted). Copying needs the accumulated chain text, which only a **sink** receives, so it is the new passthrough sink `.c.c`: it writes the same sanitized, `--head`-trimmed context an AI sink would receive to the system clipboard and leaves the context unchanged, so it can sit before another sink (`prompt .tse khodro .tse.analyze .c.c`). Because one name has one role, `copy` is not a `.clipboard` subcommand — `.clipboard copy` is a usage error that points at `.c.c`; both files share `src/prompts/clipboard.cpp`. Tests: the `clipboard_prompt` ctest (`tests/test_clipboard_prompt.sh`, end-to-end paste/copy through a stubbed xclip, blank edges included) plus the registration cases in `test_chaining.cpp`.
- `prompt` sinks — `.ai.chatgpt`/`.ai.dseek`/`.ai.gap`/`.ai.grok`/`.ai.kimi` are now native chain segments that wait for everything before them, send the accumulated chain text to the site's signed-in web session, and make the answer the context for later segments. Sink flags are dispatcher-owned and identical for every sink: `--on-error abort|continue|skip` (default `abort`; a failed source batch taints the context and each later sink applies its own policy), `--with-context`, `--show-context` and `--head N`; output defaults to sink answers plus trailing segments no later sink consumed, and `--print-prompt` is an offline dry run. The sink layer (`src/sdk/sink_types.hpp`, `sink.hpp`, `register_sink`, `plan_chain`) is generic — `ai.cpp` only supplies provider names — and `process::command` gained `on_stdout`/`on_stderr` tee callbacks with timeout-safe `poll` draining so answers stream live while still being stored. Instructions come from a preceding `.note` or `--system`; positional prompt text is rejected, reasoning stays on stderr and is never chained, and stored context/clipboard text stays sanitised.
- AI sinks render like a direct `ai.*` run: when prompt's stdout is a terminal they pass `bin/ai --tty` plus the terminal's `--width`/`--height` (from `TIOCGWINSZ`), so rich Markdown, colour, tool notes and reasoning behave as in a standalone call instead of degrading to plain text. The bare answer travels out of band through a new hidden `--context-file`, which prompt reads back into `r.out`: the chain context and clipboard stay free of ANSI/rich frames (and of `--json` event lines), partial answers still chain after a failure, piped runs stay plain, and the temporary file is removed on every path.

### Changed

- **One text-fold rule for every emitted segment** — the dispatcher's block fold is now a single function, `text::append_block` (`prompts/src/core/strings.{hpp,cpp}`), shared by the chain context (`chain_state::append`), the stdout accumulator, the clipboard builder (`output_emitter`) and the history replay (`history::final_output`): a block is trimmed of leading **and** trailing newlines, an empty segment contributes nothing (no stray separator), consecutive blocks are separated by exactly one blank line, and the buffer ends with exactly one newline. Previously only the chain context trimmed both sides while stdout, the clipboard and `history` trimmed trailing newlines only, so a prompt whose output began with a newline (`prompt .c.p` on a clip with blank edges, `delegate`, `cli`, `clang-tidy`, …) printed those leading blanks even though the context a sink saw was clean. `.c.p` additionally normalizes its paste before applying `--head N`, so the cap counts real content lines. Tests: `tests/test_strings.cpp` (`append_block`/`strip_newlines`), the `output_fold` ctest (`tests/test_output.sh`: trim on both sides, one blank line between segments, an empty segment adds nothing, `.history` byte-matches stdout) and the blank-edge cases in `test_clipboard_prompt.sh`.
- Dispatcher internals split along one seam each: the fork/pipe/`drain_all`/decode machine that runs a parallel batch is now one `run_parallel()` helper (both chain paths used to carry their own copy of the whole fd lifecycle), the ~90-line environment initializer left `main.cpp` for `src/environment.cpp` (`make_environment()`), and the pasted-text → instrument policy became `clipboard::detect_identifier()` in `core/clipboard.cpp` with `tests/test_clipboard.cpp` covering URLs, ISIN/insCode, Persian symbols, CR/LF and the rejections. `drain_all()` builds its `pollfd` mirror once per drain instead of once per poll round, and a parallel child that dies before writing its blob now reports the signal or exit status instead of a bare "produced no result".
- The prompt registry is fixed-capacity on purpose and now **fails loudly**: registering more than `prompt_registry_capacity` (128) prompts aborts at startup with a message instead of silently dropping the extra registration, and `test_chaining` asserts the catalog fits.
- `prompt ask-for-help` is now **`prompt delegate`**. Same prompt, same output: describe the problem on stdin (or the clipboard) and the local model composes the `prompt` command that gathers the context a stronger AI needs. The old name is gone — there is no alias — and the prompt still excludes itself from the catalog it embeds, so `.delegate` never lists itself as a chaining option
- `bin/ai.chatgpt` now applies the site's JSON-patch frames (`{"o": "patch", "v": [{"p": "/message/content/parts/0", "o": "append", …}]}`) instead of emitting only whole `message` frames. The patch frames carry the tail of a streaming answer, so any reply the site streamed that way (notably turns that run the code interpreter, which `--file` tends to trigger) was silently truncated to its first fragment
- Prompt names now follow the tools: **`stock` → `tse.analyze`** and **`intraday` → `tse.intraday`**. `tse.analyze` is now a data-free lens: it only prints the institutional-analyst instructions and takes no arguments, so `prompt .tse فولاد .tse.analyze` embeds the dataset exactly once (no shared state or chain special-casing). `tse.intraday` collects its dataset with **`bin/tse.intraday`** (per-minute bars rebuilt from the tape, per-bar VWAP, the official daily row, daily حقیقی/حقوقی, optional `--depth`) instead of `tse all`, matching the tool of the same name, and its instructions were rewritten for that dataset. `prompt auto` now dispatches a stock identifier to `tse` + `tse.analyze`
- Layout: the native C++ dispatcher moved from `cpp_prompt/` to **`prompts/`** and is now the installed `prompt` command; the original bash implementation moved to **`prompts-shell/`** (dispatcher `prompts-shell/prompt.sh` plus `_common.sh` and the `*.sh` prompts) and has since been removed entirely. `cmake --install prompts/build --prefix "$HOME/cmd" --component prompt` drops the binary at `bin/prompt` (gitignored), so `prompt` on `PATH` is the native dispatcher; the native `--help` no longer claims to scan `$XDG_CONFIG_DIRS/prompts` or run `.sh`/`.txt`/`.md` files
- `prompts/` structure: a prompt is one file that implements and registers itself — `static void execute_<name>(prompt::view const&, prompt::result&)` writes `r.out`/`r.err` and **throws** on failure (`usage_error`/`soft_error`/`prompt_error` in `sdk/errors.hpp`); the dispatcher catches them once in `main.cpp`'s chain loop. The `prompt_output` return struct, the 76 per-prompt header pairs, the umbrella `prompts/prompts.hpp` and the central `prompt_entry.cpp`/`register_batch_*.cpp` registrars are all gone; each `src/prompts/<name>.cpp` ends with a single `prompt::register_prompt(...)` call at static-init time (hence `prompt_lib` is an OBJECT library, so the registrars aren't dropped)
- Subprocesses run through fork/exec instead of `popen` + shell-quoting: argv reaches the child verbatim, child stderr can be captured or merged, and timeouts are enforced
- Repeated `output += "literal" + x + "literal"` sites (143) converted to `std::format`; lying `noexcept` qualifiers removed (they aborted on `std::stoull`/`std::regex` failures) and the numeric parsing hardened
- `prompts/` prompt sources tidied: contiguous `output += "…\n"` prologues are single raw string literals, adjacent `std::format` calls are merged, the `prompt_context` service wrappers became free functions taking the environment, and `infer_lang` returns `std::string_view`
- `tse` fetches through `python3 bin/tse … --markdown` and `tse.intraday` through `python3 bin/tse.intraday` exactly like the bash scripts (the tools' stderr is inherited); skill frontmatter parsing and the KDE clipboard path are C++/`qdbus` — `prompts` no longer embeds or links libpython (`src/core/python.cpp`, `src/tse/tse_python.cpp` and the LeakSanitizer suppressions deleted)
- Chain semantics corrected and documented in `AGENTS.md`: chained prompts share the ORIGINAL piped stdin (nobody feeds a prompt's output into the next); a prompt that reads stdin spends the pipe for later prompts with `v.in.spend()`, reported natively through `segment_outcome::stdin_consumed` (or `prompt_error::stdin_consumed()` when the prompt threw)
- `bin/prompt auto` stock-identifier extraction bug fixed in `prompts-shell/auto.sh`
- `bin/tse` HTTP client negotiates and decompresses gzip/deflate responses: the TSETMC CDN gzips its JSON, so a busy intraday tape that decodes to ~15 MB arrives as ~0.5 MB on the wire, and the response-size guard now bounds the decoded body. `Client.get`/`json` take a per-call `max_bytes` (the tape endpoints need more than the 6 MB default)
- `bin/tse`, `bin/tse.snapshot` and `bin/tse.codal` now print every market date and timestamp in Jalali (Shamsi) with ASCII digits and `/` separators (`1405/07/26 14:45:26`) instead of Gregorian — the quote's `trade_date`, the daily-history and corporate-action `date` columns, `nav_as_of`, `fetched_at`/`retrieved_at`, and the date in `.stock` file names. Clock-only fields (`trade_time`, `nav_as_of_time`, index `time`) stay `HH:MM:SS`, legacy ISO `fetched_at` in older `.stock` files is still parsed, and no parallel Gregorian field is emitted; `bin/tse.find` and the prompt prose are unchanged

### Fixed

- `bin/ai.gap` no longer aborts a turn while the model runs a server-side tool. GapGPT executes `file_retrieval` itself, so the websocket goes quiet for seconds at a time; the adapter then falls back to `GET /api/v1/get_chat/token/<token>` (`_poll`), but that fallback (a) sent cookie-only headers and got `HTTP 401: Authentication credentials were not provided.` on every call instead of the `accessToken` bearer the upload/history paths use, so it could never read a turn, and (b) caught only `net.StreamError`, so a raw edge failure (`curl: (28) Operation timed out`, a reset) escaped `_poll` → `_read_turn` → `send` and surfaced as `GapGPT stream failed: …` — `bin/ai` exited 1 and `prompt .verify .ai.gap` printed `ai.gap: exited with status 1` even though the site finished the answer seconds later. The conversation now builds its REST headers with `provider.history_headers()` (bearer included), a failing poll is swallowed (logged under `--debug`) so the socket stays the primary path and the next quiet slice retries, and the turn only ends on a real completion or its own timeout. Tests: `prompts/tests/test_ai_gap.py` (bearer headers, a transport error and a `StreamError` both non-fatal, `_read_turn` surviving a raising poll), wired as the `ai_gap_unit` ctest.
- `drain_all` (the parallel-batch pipe drain) no longer blocks on a child that says nothing yet. It erased an entry from `polled` but not from the parallel `revents` vector, so after one child reached EOF the next ordinal tested its neighbour's *stale* `revents` and issued a blocking `read()` on a pipe `poll()` had not reported ready — a fast child followed by a slow one hung the batch. The two vectors are now erased together, and every fd is closed exactly once (it used to be closed inside the loop *and* in the trailing sweep). `tests/test_facts.cpp` covers a fast child plus a child that stays silent past the first EOF and then writes three pipe buffers.
- Tool-backed `tse` prompts no longer fail silently: a live fetch now gets an explicit 10-minute backstop instead of `run_command`'s 30-second default (which killed a full `tse all` fetch mid-flight and printed nothing), and a timeout, non-zero exit or empty dataset reports `prompt <name>: bin/<tool> …` instead of an empty `soft_error`; `.tse.codal` gets 120 s because its own retry deadline is 60 s. A sink that is not run because an earlier prompt failed (`--on-error abort`, or skipped with `skip`) now names itself on stderr (`prompt: .save not run: …`), so `.save` never appears to do nothing — and when it is reached with `--on-error continue`, its existing empty-context guard still refuses to write.
- `bin/tse.codal` no longer gives up when Codal resets a connection: `search.codal.ir` intermittently answers `ECONNRESET` (errno 104, `<urlopen error [Errno 104] Connection reset by peer>`) and tarpits requests for seconds, and only search/report GETs were retried (3 attempts, 12 s timeout) while the captcha `begin`/`Captcha`/`end` calls had no retry at all and a truncated body (`http.client.IncompleteRead`) escaped as a traceback. All three transport paths now share one retry policy — `CODAL_RETRIES` attempts (5), `CODAL_TIMEOUT` (30 s), `CODAL_DEADLINE` (60 s wall clock), jittered exponential backoff, a fresh socket per attempt with the cookie session kept, 408/425/5xx treated as retryable and a per-host cooldown after a failure — and a failure reports how many attempts and seconds it spent (`Cannot reach search.codal.ir after 5 attempt(s) in 61s (Connection reset by peer); …`). Captcha and search requests share one 4 s per-host pace key (they used to run independently). Successful artifacts are cached under `${XDG_CACHE_HOME:-~/.cache}/tse/codal` (`CODAL_CACHE_DIR`): entries younger than `CODAL_MAX_AGE` (default 6 h, `--max-age`) are reused, older ones are refetched but still serve as a fallback when the live fetch keeps failing, and any cached result carries a `cache` note with its Jalali fetch time, age, staleness and the live error — rendered above the Codal block in `tse.codal`'s Markdown. An outage is never cached as an empty report, `--refresh` forces a live fetch, `--cache-only` never goes online, and `tse.codal cache path|list|clear` inspects or purges the cache, and a Codal failure is reported under `errors` instead of aborting the rest of the snapshot
- `bin/ai.dseek` now finishes an answer the site cuts short: DeepSeek ends such a stream with `response/status` short of `FINISHED` and a `close` event whose `click_behavior` is not `none` — the web UI's `Continue` button, which the script ignored, so a truncated reply looked complete. It now posts `/api/v0/chat/continue` with the assistant `message_id` (its own `X-DS-PoW-Response`) and appends the continuation through the same fragment parser, dropping the repeated snapshot prefix so nothing is emitted twice; up to 8 continuations, each shown as a `continue` tool note
- `bin/ai.gap` on a flaky edge or a large prompt: the WebSocket was written with the 2-second *read* slice as its timeout, so a big piped prompt (the site's ArvanCloud edge takes ~17 s to accept a 700 KiB frame) died with `The write operation timed out`, and one stalled handshake (`Invalid status line: 'd'`) aborted the whole run. Writes now get their own 60 s timeout, the 2 s slice is applied only around `recv()`, and the connect plus the first frame are retried up to 3 times with backoff
- `tse.resolve` phonetic finglish matching and finglish completion tokens: `mobin` now resolves to `مبین` (the literal forward key is `mbin`) — Latin key scoring uses length-aware `ratio` instead of `WRatio`'s substring bonus, short name-derived keys (`bin`, `min`, `si`) are dropped from the index, and a close spelling of a symbol key counts as a finglish match, so it no longer ties with name-based fuzzy candidates. `--complete` keeps the typed Latin form (`foolad-IRO1FOLD0001`) and completes a partial ISIN after a separator (`foolad-IRO1F` → `foolad-IRO1FOLD0001`); ISIN/insCode prefixes still emit the canonical Persian token
- `prompt ask-for-help` copies its output to the clipboard again: the native port set `no_clipboard` unconditionally, while the bash reference only suppresses the copy of the *inner* `list.sh` catalog it embeds (`PROMPT_NO_CLIPBOARD_FILE=/dev/null`) — `list`/`list-prompts` remain the only prompts that opt out
- `fs::bin_tool` now finds repo tools when the binary is **installed** in `bin/`: it looked in `exe_dir/bin/<tool>` (`bin/bin/tse`) instead of `exe_dir/<tool>`, so `prompt tse` (and every tool-invoking prompt) failed outside the build tree with `python3: can't open file '.../tse'` — the miss also fell back to a bare name, which callers then opened relative to the cwd. The `$PATH` fallback now resolves to an absolute path, and `tests/test_fs.cpp` locks the installed/build/git-root/PATH layouts
- Empty-but-piped stdin handling: `note` (and other stdin-reading prompts) print the same blank embed block as `embed_stdin || true` when the pipe is empty, keeping chained output byte-identical to bash
- `resolve_input_file` matches the bash implementation (cwd → git root → `git ls-files | fzf -f`)
- `prompt tse` in the C++ dispatcher honours `--head`: it was parsed but never applied, so `prompt tse --head N <snapshot>` printed the full rendered snapshot instead of the capped one
- Debug-build `-Wall -Wextra -Wshadow` warnings from `process.cpp` (unused `quote_for`) and `skill.cpp` (a shadowed loop variable) cleared
- `--head 0` audited across every prompt: context trimming now mirrors `sed -n "1,0p"` (keep line 1) via `trim_context`/`trim_context_nl`, while the paths that really run `head -n N` (`run`, `clang-tidy`) keep nothing — matching bash byte-for-byte (`std::optional<std::size_t>` distinguishes "unset" from a real `0` cap)
- `prompt paths` consumed `--context`/`--head` values as paths (the flag was read but its operand was not) — a file's context and head cap are now applied and the operand no longer leaks into the path list
- `prompt tse.intraday --head N` was parsed but never applied (the cap was silently dropped); `--head` is now validated like `parse_arguments` and honoured through `trim_context`
- `prompt list`/`list-prompts` rejected `--head N` (bash strips it via `init_prompt`→`parse_arguments`); both now accept and validate it
- `prompt note --head` with no value treated `--head` as note text; it now fails with `Missing value for --head` (exit 2) like `note.sh`
- `prompt clang-tidy --head N` kept a trailing blank line bash drops (`head -n N` inside `$(...)` strips it)
- `prompt skill <unknown>` no longer leaks `bin/ai-find-skills`'s `# full JSON: <tmpfile>` stderr note (the bash download path redirects it to `/dev/null`)
