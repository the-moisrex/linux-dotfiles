### Added

- `bin/md.extract` — pull blocks out of Markdown (stdin or files): fenced code (` ``` `/`~~~`, blockquoted and list-indented fences included), sections (`--kind section --heading X`, subsections by default), GFM tables and frontmatter. Each block is parsed with its context — the enclosing heading path plus the prose paragraph before and after — so "the csv block whose intro says X" is two filters: `--lang csv --before "monthly totals"`. Selectors are independent and AND-ed (`--kind`, `--lang`, `--heading`, `--under`, `--before`, `--after`, `--title`, `--grep`, `--indented`, case-insensitive regex with `-F/--literal`), `--lang` compares families (`c++`/`cxx`/`hpp` → `cpp`, `bash`/`console` → `sh`, `patch` → `diff`, `py` → `python`; `any` = untagged, `*` = all) and `--guess` sniffs untagged bodies. `--list` numbers the rows of the current selection, so `-n N` (`2-5`, `1,4`, `-1`, `--first`/`--last`) re-selects a row, `--pick` opens fzf and `--one` requires a single match. Output is the body alone (pipe into `git apply`/`jq`); `--fence` re-emits the original fence, `--with-heading`/`--with-intro` add provenance, `--json`/`--jsonl` emit full records, and `-o FILE`/`--out-dir DIR` (named from `title=`, the heading or `<lang>-<index>`, with `--ext`, `--force`, `--dry-run`) write matches to disk. Exit status is grep-like (`0` matched, `1` nothing, `2` usage error), unclosed fences warn on stderr without failing, and the CLI/JSON/exit-code contract is meant to be called from a native `prompt` segment later.

- `bin/ai.debate` / `prompt .ai.debate` — two or more AIs verify each other's answers in a relay. The first provider answers the question; its answer goes to the next provider as `Another AI said:` together with a verification request; each participant keeps its **own** conversation, so later turns only carry the newest answer, and the ring runs for `--rounds N` (default 2) or until every AI's `VERDICT: AGREE` line agrees (`--until-agree`). The leading positionals are providers (`chatgpt`, `grok`, `deepseek`/`dseek`, `gap`, `kimi`), the rest is the question (or stdin); `--context last|all` (`--transcript`) picks the last answer or the labelled transcript for the chain context and clipboard, `-m PROVIDER=MODEL`/`-s`/`-f` configure each side, `--instruction`/`--no-instruction` replace the verification request, and `--print-prompt`/`--print-session`/`--list` are offline dry runs. Sessions load for every provider up front; a failed or empty turn stops the relay with the last complete answer in the hidden `--context-file` side channel the `.ai.debate` sink reads back (it forwards `--tty`/`--width`/`--height` like `.ai.*`). The relay reuses `bin/ai/cli.py`'s turn/streaming/renderer/context helpers (with a new `fields` tag on `--json` events), so the single-provider commands and the relay run the same path. A debate starts fresh chats by default; `-c/--continue` reopens each participant's chat from the last debate between the same provider set (state in `$XDG_STATE_HOME/ai/debate-<providers>.json`, written after every successful turn), and `--new` discards it.
- `prompt length` (chained as `.length`) — tells the AI how long (or short) its answer should be. A target is a number with an optional unit — words by default, or lines, sentences, paragraphs, characters and tokens — accepting `200`, `10 lines`, `--words 200`, compact suffixes (`200w`, `10l`, `3p`, `500c`, `300t`), thousands (`2k`) and number words (`a few sentences`, `a couple of paragraphs`), or a preset — length presets (`tiny`, `short`, `medium`, `long`) and shape presets (`one-liner`, `sentence`, `paragraph`, `bullets`, `title`, `tweet`, `sms`, `email`, `letter`, `blog`, `article`, `report`, `essay`, `abstract`, `outline`, `notes`, `caption`, `bio`, `commit`, `changelog`, `thread`, `tldr`) — with no target defaulting to `medium` (about one or two paragraphs). Targets are approximate by default (`about 200 words`); prefix with `=` or pass `--exact` for a hard target, and `--max`/`--min` only cap or only extend. Against a chain it is just another instruction segment (`prompt .fix src/main.cpp .length 200`), and it also works as the instruction a later `.ai.*` sink sends.
- `prompt .save [FILE|DIR]` — a passthrough chain sink that writes the accumulated context (the same sanitized, `--head`-trimmed text an AI sink receives) to disk and leaves it unchanged for later segments, so `prompt .files a.cpp .save review.md .ai.grok` saves the files and still sends them to Grok. With no target it derives a name from the nearest successful preceding prompt's `save_hint`: `tse-<symbol>.md` from the `tse` family, the snapshot stem for `.stock` input, or the first embedded file's stem from `.files`, falling back to `prompt-<timestamp>.md`. A target that is an existing directory, ends in `/`, or has no file extension is treated as a directory and created automatically; an existing non-directory or a name with an extension is the exact file, and `--dir`/`--file` override the heuristic. Hints are sanitized basenames, missing parent directories are created, and a dispatcher preflight creates and checks the destination for writability before any prompt runs (so a path component that is a file fails fast with `exists but is not a directory`). Existing files are refused unless `--force` is passed (`--allow-empty` writes an empty context). A successful silent sink is a chain no-op: it does not clear the context or a source-batch failure taint, and it adds no output separator.
- `prompt .clear` / `.flush` — context-reset chain sinks for running several independent sections in one invocation. `.clear` discards the accumulated context and everything a later sink would inherit (the filename hint, the redaction note, the barrier stderr and the source-batch failure taint) while keeping output already printed, the clipboard and the exit status, so `prompt ... .ai.grok .save one.md .clear ... .ai.grok .save two.md` behaves like two runs sharing one output stream; a leading `.clear` also drops unconsumed piped stdin. `.flush [FILE|DIR] [save options]` is exactly `.save` followed by `.clear` — same target rules, filename hints, `--force`/`--allow-empty`/`--dir`/`--file` and the same preflight — with the reset applied only after the write succeeds, so a refused or failed save leaves the context intact. The reset travels through `prompt_context::clear_context` (an output flag like `no_clipboard`), so the sink declares it and the dispatcher, which owns the accumulated state, applies it.
- `prompt` sinks — `.ai.chatgpt`/`.ai.dseek`/`.ai.gap`/`.ai.grok`/`.ai.kimi` are now native chain segments that wait for everything before them, send the accumulated chain text to the site's signed-in web session, and make the answer the context for later segments. Sink flags are dispatcher-owned and identical for every sink: `--on-error abort|continue|skip` (default `abort`; a failed source batch taints the context and each later sink applies its own policy), `--with-context`, `--show-context` and `--head N`; output defaults to sink answers plus trailing segments no later sink consumed, and `--print-prompt` is an offline dry run. The sink layer (`src/sdk/sink_types.hpp`, `sink.hpp`, `register_sink`, `plan_chain`) is generic — `ai.cpp` only supplies provider names — and `process::command` gained `on_stdout`/`on_stderr` tee callbacks with timeout-safe `poll` draining so answers stream live while still being stored. Instructions come from a preceding `.note` or `--system`; positional prompt text is rejected, reasoning stays on stderr and is never chained, and stored context/clipboard text stays sanitised.
- AI sinks render like a direct `ai.*` run: when prompt's stdout is a terminal they pass `bin/ai --tty` plus the terminal's `--width`/`--height` (from `TIOCGWINSZ`), so rich Markdown, colour, tool notes and reasoning behave as in a standalone call instead of degrading to plain text. The bare answer travels out of band through a new hidden `--context-file`, which prompt reads back into `ctx.out`: the chain context and clipboard stay free of ANSI/rich frames (and of `--json` event lines), partial answers still chain after a failure, piped runs stay plain, and the temporary file is removed on every path.
- Chain segments without piped stdin now run **in parallel** (each in a forked child, never a thread, because `process::command` forks) and their outputs, stderr and exit statuses are still emitted in argv order; a piped stdin keeps the chain sequential so the existing spend-once rule is unchanged. `prompt .yt XXX .tse YYY` now fetches both at once.
- The `tse`-family data prompts share arguments: `.tse.codal` and `.tse.intraday` borrow the nearest `.tse`/`.tse.codal`/`.tse.intraday` symbol before consulting the clipboard, so `prompt .tse foolad .tse.codal .tse.intraday .tse.analyze` is equivalent to repeating `foolad` after each prompt. `prompt_context` exposes the chain (`chain`, `chain_index`) to every prompt for this kind of sibling lookup.
- `prompt tse.codal` and `bin/tse.codal` — Codal is now opt-in. The `codal` tool was renamed to `bin/tse.codal` (`search`/`statements`/`snapshot`/`cache`, identifiers resolved through `tse.resolve`, `snapshot --markdown` renders the prompt dataset, and the ROE/margin/debt/book-value/P-B ratios computed from extracted statement rows now live under `codal.derived_ratios`), while `bin/tse`/`prompt tse` fetch market data only: the `tse codal` subcommand and the `--top`/`--refresh-codal`/`--no-codal`/`--without codal` flags are gone. The new data-only `prompt tse.codal` wraps `tse.codal snapshot --markdown` with clipboard fallback, `--top N` (1–20), `--fund`, `--refresh` and `--head N`; chain `prompt .tse فولاد .tse.codal .tse.analyze` (the Codal prompt borrows the market dataset's symbol). Old `.stock` snapshots that already contain a Codal block still render it.
- `bin/ai.*` oversized prompts are now uploaded as text files by default: a prompt above the provider's conservative UTF-8 budget (ChatGPT 48 KiB, GapGPT 24 KiB, Grok 64 KiB, DeepSeek/Kimi 256 KiB, chosen from each site's measured single-message limit; Grok conservatively, since its upload endpoint is region-blocked here) is written to a temporary `.txt` by `bin/ai/promptfile.py`, sent through the existing `--file` upload path and replaced by a short pointer message, then deleted after the turn. `--prompt-file` forces the file, `--no-prompt-file` keeps the prompt inline and `--prompt-limit BYTES` overrides the budget; `HTTP 413`, GapGPT `token_limit` and the sites' context/conversation-limit errors now name the prompt size and the remedy instead of a bare status (Kimi's Chinese 200,000-character error is translated).
- `bin/ai.kimi` — Kimi (www.kimi.ai) as a fifth `ai.*` provider: replays the signed-in session (`POST /api/chat`, then the `completion/stream` SSE whose `cmpl` events carry the text), renews the 15-minute `localStorage` access token from the refresh token before each turn, uploads `-f` files through `/apiv2-files/file/upload` and references their ids in the completion body's `refs`, and folds `--system` into the first message because the site rejects a `system` role. The server threads the transcript on the chat id, so `-c`/`-i` only reuse it; a cut-short answer (the site stores it as `MESSAGE_STATUS_TRUNCATED`, its Continue button) is finished through the Connect `ContinueChat` patch stream and appended, so the text is whole
- `bin/tse` derived technicals, multi-session breadth and the last session's order books: `tse all` now emits a `Technicals / تحلیل تکنیکال` section (returns over 1w/1m/3m/6m/1y, 20/60-day realised volatility annualised, ATR(14) in rial and percent, MA20/50/200 with the distance from each, RSI(14), the 52-week high/low and price position, the worst 1-year and 3-year drawdown and the median 60-day overnight gap) computed from the same adjusted history table — a value that needs more sessions than were fetched stays null instead of being labelled with a shorter window. `market_context.breadth_history` adds whole-market breadth for the five sessions before the newest one (one concurrent `ClosingPrice/GetInstrmentsHistoryInDay` request per session, holidays skipped), and `last_book` carries the last completed session's opening-auction (09:00:00) and close (12:30:00) order books rebuilt from the same per-level `BestLimits/{insCode}/{date}` stream `tse.intraday` replays: best bid/ask with sizes and exchange order counts, spread, 5-level depth and imbalance, plus the stream's coverage — a stream that does not reach the close is an edge still publishing the date, so the close snapshot is omitted and the coverage reported rather than mislabelled, and a truncated edge is retried on a fresh connection. `--without book` skips the new section (`--without book,statistics,breadth`), and `prompt tse` forwards `--without NAME` to the tool

Every session gets a `Session:` line (first trade, high/low with their times, the close's location inside the day's range as CLV, the share of volume traded at or above the tape VWAP, and the opening gap against the previous close), a `Structure:` line (the 5/15/30-minute opening ranges and the market-profile value area — POC, the 70% band and its width in price levels) and a `Largest prints:` line (the three biggest trades by rial value); today's static daily price limits (`Instrument/GetInstrumentInfo.staticThreshold`, `psGelStaMin`/`psGelStaMax`) are printed in the header labelled as today's band, with the live price's distance from each limit (and `at the … limit` when locked). `--flow` gains a `cum_net_shares` running-delta column next to `net_shares`, and the `tse.intraday.analysis` lens explains the new lines, the value area/opening-range reading and the limit/صف check

The client-type series starts 2018-11-26 and a few later sessions are missing upstream, so those cells stay empty (missing = unknown, not zero); non-trading days also have no record. A failed client-type fetch no longer fails the price table, it is reported under `errors.client_type_history`

A native-only reference prompt, standalone or chained (`prompt tse فولاد .tse.times`)

- `bin/tse.intraday` — intraday (per-minute) OHLCV bars for a TSETMC instrument over one session or a range (`--days N`, `--date YYYY/MM/DD`, `--from`/`--to`), for day-to-day charting. TSETMC publishes no historical intraday aggregate, so every session — including the live one — comes from the per-trade tape (`Trade/GetTradeHistory` for completed days, `Trade/GetTrade` for the live one; `canceled` rows are dropped, rows deduplicated by trade number, trades sorted by time then trade number, aggregated locally into N-minute bars), falling back to `Trade/GetTradeIntraDay` (TSETMC's native 2-minute bars, labelled `source: live`) only when the live tape is empty. Consecutive bars with identical OHLC collapse into one `from`..`to` row, but only once a run exceeds `--collapse-threshold` (default 120 rows), so a small live or partial day keeps every minute while a full session or a locked limit day is condensed (`--collapse auto|on|off`, `--no-collapse` = `off`); collapsed rows carry a trailing `bars` column with the count they merged. `--interval auto` (the default) starts at 1 minute and coarsens through 2/3/5/6/10/15/30/60 until the collapsed total fits `--max-rows` (default 2000), reporting the chosen interval. The live session additionally prints the real-time `ClosingPriceInfo` quote (last price/time, running trades and volume, day range, running قیمت پایانی) and how far the lagging `GetTrade` tape trails it, since TSETMC serves that tape from CDN replicas that can sit minutes behind the exchange. Every bar carries `vwap_rial`, its own volume-weighted average price computed from the tape (the native 2-minute fallback publishes no turnover, so that cell stays empty), and every completed session an `Official:` line with TSETMC's daily row: قیمت پایانی (`pClosing`, the day's VWAP capped by حجم مبنا) with its timestamp, the last trade and its change against the previous close, first/range, and the trade, volume and value totals. Each session also carries its daily حقیقی/حقوقی breakdown; the output states up front what TSETMC publishes nowhere — per-minute (or per-bar) حقیقی/حقوقی, closing-auction detail (قیمت پایانی is a volume-weighted average, not an auction print) and per-instrument NAV history (only the current NAV is exposed). `--depth` adds the order book to every bar — best bid/ask with their sizes, the spread, the cumulative 5-level bid/ask depth and the imbalance, sampled at the end of each row's span — and `--depth-ladder` prints the whole ladder at each row boundary (`time,level,bid_rial,bid_shares,bid_orders,bid_cum_shares,ask_…`) with running cumulative depth, its `--max-rows` budget split across the five levels. Both come from TSETMC's per-level `BestLimits/{insCode}/{date}` update stream (5 levels and no more, published only after the close, roughly two months of history, ~440 KB gzipped per busy day), so the live session shows just its current `BestLimits/{insCode}` book; the stream begins pre-open, so the 09:00 row is the opening-auction book, and post-12:30 updates are dropped because the exchange keeps replacing levels individually after the close. An extras registry adds the surrounding context, each item individually selectable with `--with NAME[,NAME…]`/`--without NAME[,NAME…]` (`all` accepted)/`--only NAME[,NAME…]` and printed by `--extras`: `book` (on) prints two order-book summary lines per session — the opening auction sampled at the first bar's end and the close at the last trade — with best bid/ask sizes, exchange order counts (a saturated count renders `>=9,999`), spread, 5-level depth and imbalance; `orders` (on) and `opening` (on) control those counts and the auction line; `stats` (on) adds a `Context:` line with the instrument's 3-month average volume/trades/real buyers and company value/rank beside the latest published session's numbers; `index` (auto, live sessions only) adds a `Market:` line from the live market overview (TEDPIX and equal-weighted change, market trade/volume/value totals, state); `breadth` (auto, up to five published sessions at ~175 KB each) adds a per-session `Breadth (date):` line from the whole market's own daily rows; `flow` (off) adds `buy_initiated_shares`/`sell_initiated_shares`/`net_shares`/`buy_pct` columns and a `Flow (estimated):` line by classifying each trade against the best bid/ask at its moment — at/above the ask is buyer-initiated, at/below the bid seller-initiated, an inside-the-spread print goes to the side of the midpoint, and the unclassifiable remainder is reported rather than guessed (`--flow` is the shorthand and implies the book). Any extra that cannot answer is dropped with a printed reason and recorded in the JSON `extras` provenance (`used`/`skipped`); the `BestLimits` stream is validated against the session it is replayed on, and a partial stream (the endpoint resolves to several CDN edges that briefly disagree while a date is still being published) is refetched on a fresh connection and refused with a note if it still does not span the session, instead of being mislabelled as the close. `--ticks` prints the raw tape, `--profile` a price-level volume profile, `--json` JSON instead of Markdown. Sessions are fetched in parallel with retries (the tape endpoint flakily returns empty or 500) and `--days` is capped at 30; a failed session is listed under `errors` without failing the run. Identical identifier forms to `tse`/`tse.snapshot`, an Iranian IP required, no cache
- `prompt tse.intraday` now emits **only the dataset**, and the same-day trading instructions moved to the new data-free `prompt .tse.intraday … .tse.intraday.analysis` lens (the `tse`/`tse.analyze` split applied to intraday, both registered from `prompts/src/prompts/tse_intraday.cpp`). The lens takes no arguments and never fetches, and its guidance now covers the tool's default extras — the `Context:`, `Breadth (…)`, `Market:`, `Depth (auction/close/live)` and `Flow (estimated):` lines, `Skipped extras:` as missing (not zero) data, and the Lee–Ready flow estimate's unclassified remainder — instead of claiming the dataset has no market-breadth context
- `bin/ai.chatgpt`, `bin/ai.grok` and `bin/ai.dseek` — ask ChatGPT, Grok and DeepSeek from the shell by replaying each site's own web API with the browser's signed-in session: no API key, no official API and no browser at run time. One shared engine (`bin/ai/`: providers, normalised `thinking`/`text`/`tool_call`/`usage`/`done`/`error` events, a renderer and a CLI) adapts each transport — ChatGPT's `f/conversation` conduit behind the sentinel gate (requirements token, `zvt` proof-of-work and the turnstile VM, ported in `bin/ai/sentinel.py`), Grok's `wss://grok.com/ws/mgw/` WebSocket (`session.create`/`response.create`) and DeepSeek's `DeepSeekHashV1` proof-of-work plus fragment-patch stream. Prompts come from arguments or stdin; answers stream as Markdown on a TTY (reasoning dimmed, tool calls display-only), piped output keeps stdout clean with reasoning/tools on stderr, and `--json` emits one event per line; `--model`, `--system`, `--show-thinking`/`--no-thinking`, `--raw`, `--copy`, `--timeout` and the `browser.session` selectors (`--browser`/`--profile`/`--family`/`--open-only`/`--exact`, `--print-session`) are shared. `-i` keeps the conversation open and prompts in a loop (`:q` quits, `:new` resets); `-c`/`--continue` reopens the last conversation and `--new` starts a fresh one, both remembered under `$XDG_STATE_HOME/ai/<provider>.json` — ChatGPT and DeepSeek resume it by conversation/message id, while Grok (whose socket lives only for one process) replays the stored transcript
- `bin/ai.gap` — ask GapGPT (gapgpt.app) from the shell, the fourth `ai.*` provider: it drives the site's own WebSocket (`wss://gapgpt.app/ws/salam`) rather than HTTP/SSE, sending a `text_message` action, taking the chat token from `ack_new_message` and diffing the `new_message` snapshots' `response` fragments (`text` → answer, `reasoning`/`agent_turn` → thinking, `canvas`/others → display-only tool calls), with `GET /api/v1/get_chat/token/<id>` as the fallback when the socket goes quiet and a `heartbeat`/`heartbeat_ack` keep-alive. The socket is held open between turns, so `-i` continues in place and `-c` reattaches by chat token. Auth is the site's `accessToken` cookie (no API key); `--model` takes the site's own ids (`A-GAP`, `A-GPT4O`, `A-GEMINI-3-PRO`, …) or friendly labels (`gap`, `gpt-4o`, `sonnet`, `deepseek-r1`, …), and everything else (`--system`, `--json`, `--copy`, the `browser.session` selectors, `-i`/`-c`/`--new`) is shared with the other providers
- `ai.*` file uploads: `-f`/`--file PATH` (repeatable) on every `ai.*` command uploads a local file through that site's own endpoint and attaches it to the first message, so the model sees the document/image instead of only its path. `bin/ai/files.py` reads and types the file (100 MiB cap, empty files refused) and `bin/ai/net.py` gained a hand-built `multipart/form-data` encoder plus a raw-body request (curl_cffi takes no `files=`), since each site's flow differs: ChatGPT's `POST /backend-api/files` → pre-signed blob `PUT` (`x-ms-blob-type`) → `…/uploaded`, then the file id referenced from the message (images as `image_asset_pointer` parts, documents as `metadata.attachments`); Grok's `POST /rest/app-chat/upload-file` (base64 JSON) → `fileMetadataId` in `event.file_attachment_ids`; DeepSeek's `POST /api/v0/file/upload_file` (multipart behind its own `X-DS-PoW-Response`, then polled through `file/fetch_files`) → `ref_file_ids`; GapGPT's `POST /api/v1/upload_file` (multipart, `accessToken` as bearer) → `file_tokens`. Each upload is announced as a display-only `tool_call` event named `upload`, and a missing, non-regular or unreadable path fails before any network call
- `bin/browser.session` — compose a site's authenticated HTTP session (cookies via `cookies`, `localStorage`/`sessionStorage` via `browser.storage`, and a matching `User-Agent` via `browser.find`) as `json`/`cookie`/`header`, so a script can replay a site's own API calls without a browser; the `ai.*` commands use it to sign in
- `bin/browser.record` — a development-only recorder (Playwright + the system browser) that saves a page's XHR/fetch/SSE traffic with headers, bodies, full `text/event-stream` bodies and WebSocket frames, optionally typing and sending a prompt; used to derive the `ai.*` adapters' endpoints and payloads

- `bin/tse.resolve` — one identifier path for every `tse.*` tool: Persian, finglish (`foolad`, `khodro` through `bin/finglish`), fuzzy/company-name, ISIN, insCode, URL and composite `فولاد-IRO1FOLD0001` tokens resolve to the canonical symbol/ISIN/insCode/market/board. Exact → finglish → fuzzy (`rapidfuzz`, `difflib` fallback), ranked by market tier so a duplicated symbol picks the main-market listing (`فنفت` → `بازار دوم`), with candidates reported only on a real tie. The active-instrument index is cached for a week (`${XDG_CACHE_HOME:-~/.cache}/tse/instruments.json`, `--refresh`/`--clear`/`--no-cache`/`--offline`) and backfilled from a live instrument search; `--json`/`--jsonl`/`--token`/`--best` and `--complete PREFIX` support scripting and shells. `bin/tse`, `bin/tse.intraday`, `bin/tse.snapshot`, `bin/tse.find --watchlist` and the `tse`/`tse.analyze`/`tse.intraday` prompts all resolve through it, and `shell/completions.fish` now completes their symbol arguments with the readable `SYMBOL-ISIN` token.

### Changed

- `prompt ask-for-help` is now **`prompt delegate`**. Same prompt, same output: describe the problem on stdin (or the clipboard) and the local model composes the `prompt` command that gathers the context a stronger AI needs. The old name is gone — there is no alias — and the prompt still excludes itself from the catalog it embeds, so `.delegate` never lists itself as a chaining option
- `bin/ai.chatgpt` now applies the site's JSON-patch frames (`{"o": "patch", "v": [{"p": "/message/content/parts/0", "o": "append", …}]}`) instead of emitting only whole `message` frames. The patch frames carry the tail of a streaming answer, so any reply the site streamed that way (notably turns that run the code interpreter, which `--file` tends to trigger) was silently truncated to its first fragment
- Prompt names now follow the tools: **`stock` → `tse.analyze`** and **`intraday` → `tse.intraday`**. `tse.analyze` is now a data-free lens: it only prints the institutional-analyst instructions and takes no arguments, so `prompt .tse فولاد .tse.analyze` embeds the dataset exactly once (no shared state or chain special-casing). `tse.intraday` collects its dataset with **`bin/tse.intraday`** (per-minute bars rebuilt from the tape, per-bar VWAP, the official daily row, daily حقیقی/حقوقی, optional `--depth`) instead of `tse all`, matching the tool of the same name, and its instructions were rewritten for that dataset. `prompt auto` now dispatches a stock identifier to `tse` + `tse.analyze`
- Layout: the native C++ dispatcher moved from `cpp_prompt/` to **`prompts/`** and is now the installed `prompt` command; the original bash implementation moved to **`prompts-shell/`** (dispatcher `prompts-shell/prompt.sh` plus `_common.sh` and the `*.sh` prompts), where it stays runnable as a historical reference. `cmake --install prompts/build --prefix "$HOME/cmd" --component prompt` drops the binary at `bin/prompt` (gitignored), so `prompt` on `PATH` is the native dispatcher; the native `--help` no longer claims to scan `$XDG_CONFIG_DIRS/prompts` or run `.sh`/`.txt`/`.md` files
- `prompts/` structure: a prompt is one file that implements and registers itself — `static void execute_<name>(prompt_context&)` writes `ctx.out`/`ctx.err` and **throws** on failure (`usage_error`/`soft_error`/`prompt_error` in `sdk/errors.hpp`); the dispatcher catches them once in `main.cpp`'s chain loop. The `prompt_output` return struct, the 76 per-prompt header pairs, the umbrella `prompts/prompts.hpp` and the central `prompt_entry.cpp`/`register_batch_*.cpp` registrars are all gone; each `src/prompts/<name>.cpp` ends with a single `prompt::register_prompt(...)` call at static-init time (hence `prompt_lib` is an OBJECT library, so the registrars aren't dropped)
- Subprocesses run through fork/exec instead of `popen` + shell-quoting: argv reaches the child verbatim, child stderr can be captured or merged, and timeouts are enforced
- Repeated `output += "literal" + x + "literal"` sites (143) converted to `std::format`; lying `noexcept` qualifiers removed (they aborted on `std::stoull`/`std::regex` failures) and the numeric parsing hardened
- `prompts/` prompt sources tidied: contiguous `output += "…\n"` prologues are single raw string literals, adjacent `std::format` calls are merged, the `prompt_context` service wrappers became free functions taking the context, and `infer_lang` returns `std::string_view`
- `tse` fetches through `python3 bin/tse … --markdown` and `tse.intraday` through `python3 bin/tse.intraday` exactly like the bash scripts (the tools' stderr is inherited); skill frontmatter parsing and the KDE clipboard path are C++/`qdbus` — `prompts` no longer embeds or links libpython (`src/core/python.cpp`, `src/tse/tse_python.cpp` and the LeakSanitizer suppressions deleted)
- Chain semantics in both dispatchers corrected and documented in `AGENTS.md`: chained prompts share the ORIGINAL piped stdin (nobody feeds a prompt's output into the next); a prompt that reads stdin (`read_stdin`/`embed_stdin`) spends the pipe for later prompts, reported natively via `prompt_context::stdin_consumed` (or `prompt_error::stdin_consumed()`)
- `bin/prompt auto` stock-identifier extraction bug fixed in `prompts-shell/auto.sh`
- `bin/tse` HTTP client negotiates and decompresses gzip/deflate responses: the TSETMC CDN gzips its JSON, so a busy intraday tape that decodes to ~15 MB arrives as ~0.5 MB on the wire, and the response-size guard now bounds the decoded body. `Client.get`/`json` take a per-call `max_bytes` (the tape endpoints need more than the 6 MB default)
- `bin/tse`, `bin/tse.snapshot` and `bin/tse.codal` now print every market date and timestamp in Jalali (Shamsi) with ASCII digits and `/` separators (`1405/07/26 14:45:26`) instead of Gregorian — the quote's `trade_date`, the daily-history and corporate-action `date` columns, `nav_as_of`, `fetched_at`/`retrieved_at`, and the date in `.stock` file names. Clock-only fields (`trade_time`, `nav_as_of_time`, index `time`) stay `HH:MM:SS`, legacy ISO `fetched_at` in older `.stock` files is still parsed, and no parallel Gregorian field is emitted; `bin/tse.find` and the prompt prose are unchanged

### Fixed

- Tool-backed `tse` prompts no longer fail silently: a live fetch now gets an explicit 10-minute backstop instead of `run_command`'s 30-second default (which killed a full `tse all` fetch mid-flight and printed nothing), and a timeout, non-zero exit or empty dataset reports `prompt <name>: bin/<tool> …` instead of an empty `soft_error`; `.tse.codal` gets 120 s because its own retry deadline is 60 s. A sink that is not run because an earlier prompt failed (`--on-error abort`, or skipped with `skip`) now names itself on stderr (`prompt: .save not run: …`), so `.save` never appears to do nothing — and when it is reached with `--on-error continue`, its existing empty-context guard still refuses to write.
- `bin/tse.codal` no longer gives up when Codal resets a connection: `search.codal.ir` intermittently answers `ECONNRESET` (errno 104, `<urlopen error [Errno 104] Connection reset by peer>`) and tarpits requests for seconds, and only search/report GETs were retried (3 attempts, 12 s timeout) while the captcha `begin`/`Captcha`/`end` calls had no retry at all and a truncated body (`http.client.IncompleteRead`) escaped as a traceback. All three transport paths now share one retry policy — `CODAL_RETRIES` attempts (5), `CODAL_TIMEOUT` (30 s), `CODAL_DEADLINE` (60 s wall clock), jittered exponential backoff, a fresh socket per attempt with the cookie session kept, 408/425/5xx treated as retryable and a per-host cooldown after a failure — and a failure reports how many attempts and seconds it spent (`Cannot reach search.codal.ir after 5 attempt(s) in 61s (Connection reset by peer); …`). Captcha and search requests share one 4 s per-host pace key (they used to run independently). Successful artifacts are cached under `${XDG_CACHE_HOME:-~/.cache}/tse/codal` (`CODAL_CACHE_DIR`): entries younger than `CODAL_MAX_AGE` (default 6 h, `--max-age`) are reused, older ones are refetched but still serve as a fallback when the live fetch keeps failing, and any cached result carries a `cache` note with its Jalali fetch time, age, staleness and the live error — rendered above the Codal block in `tse.codal`'s Markdown. An outage is never cached as an empty report, `--refresh` forces a live fetch, `--cache-only` never goes online, and `tse.codal cache path|list|clear` inspects or purges the cache, and a Codal failure is reported under `errors` instead of aborting the rest of the snapshot
- `bin/ai.dseek` now finishes an answer the site cuts short: DeepSeek ends such a stream with `response/status` short of `FINISHED` and a `close` event whose `click_behavior` is not `none` — the web UI's `Continue` button, which the script ignored, so a truncated reply looked complete. It now posts `/api/v0/chat/continue` with the assistant `message_id` (its own `X-DS-PoW-Response`) and appends the continuation through the same fragment parser, dropping the repeated snapshot prefix so nothing is emitted twice; up to 8 continuations, each shown as a `continue` tool note
- `bin/ai.gap` on a flaky edge or a large prompt: the WebSocket was written with the 2-second *read* slice as its timeout, so a big piped prompt (the site's ArvanCloud edge takes ~17 s to accept a 700 KiB frame) died with `The write operation timed out`, and one stalled handshake (`Invalid status line: 'd'`) aborted the whole run. Writes now get their own 60 s timeout, the 2 s slice is applied only around `recv()`, and the connect plus the first frame are retried up to 3 times with backoff
- `tse.resolve` phonetic finglish matching and finglish completion tokens: `mobin` now resolves to `مبین` (the literal forward key is `mbin`) — Latin key scoring uses length-aware `ratio` instead of `WRatio`'s substring bonus, short name-derived keys (`bin`, `min`, `si`) are dropped from the index, and a close spelling of a symbol key counts as a finglish match, so it no longer ties with name-based fuzzy candidates. `--complete` keeps the typed Latin form (`foolad-IRO1FOLD0001`) and completes a partial ISIN after a separator (`foolad-IRO1F` → `foolad-IRO1FOLD0001`); ISIN/insCode prefixes still emit the canonical Persian token
- `prompt ask-for-help` copies its output to the clipboard again: the native port set `no_clipboard` unconditionally, while the bash reference only suppresses the copy of the *inner* `list.sh` catalog it embeds (`PROMPT_NO_CLIPBOARD_FILE=/dev/null`) — `list`/`list-prompts` remain the only prompts that opt out
- `fs::bin_tool` now finds repo tools when the binary is **installed** in `bin/`: it looked in `exe_dir/bin/<tool>` (`bin/bin/tse`) instead of `exe_dir/<tool>`, so `prompt tse` (and every tool-invoking prompt) failed outside the build tree with `python3: can't open file '.../tse'` — the miss also fell back to a bare name, which callers then opened relative to the cwd. The `$PATH` fallback now resolves to an absolute path, and `tests/test_fs.cpp` locks the installed/build/git-root/PATH layouts
- Empty-but-piped stdin handling: `note` (and other stdin-reading prompts) print the same blank embed block as `embed_stdin || true` when the pipe is empty, keeping chained output byte-identical to bash
- `resolve_input_file` matches the bash implementation (cwd → git root → `git ls-files | fzf -f`)
- `prompt tse` in the C++ dispatcher honours `--head`: it was parsed but never applied, so `prompt tse --head N <snapshot>` printed the full rendered snapshot instead of the capped one
- Debug-build `-Wall -Wextra -Wshadow` warnings from `process.cpp` (unused `quote_for`) and `skill.cpp` (a shadowed loop variable) cleared
- `--head 0` audited across every prompt: context trimming now mirrors `sed -n "1,0p"` (keep line 1) via `trim_context`/`trim_context_nl`, while the paths that really run `head -n N` (`run`, `clang-tidy`) keep nothing — matching bash byte-for-byte (`std::optional<std::size_t>` distinguishes "unset" from a real `0` cap)
- `prompt paths` consumed `--context`/`--head` values as paths (the flag was read but its operand was not) — a file's context and head cap are now applied and the operand no longer leaks into the path list
- `prompt tse.intraday --head N` was parsed but never applied (the cap was silently dropped); `--head` is now validated like `parse_arguments` and honoured through `trim_context`
- `prompt list`/`list-prompts` rejected `--head N` (bash strips it via `init_prompt`→`parse_arguments`); both now accept and validate it
- `prompt note --head` with no value treated `--head` as note text; it now fails with `Missing value for --head` (exit 2) like `note.sh`
- `prompt clang-tidy --head N` kept a trailing blank line bash drops (`head -n N` inside `$(...)` strips it)
- `prompt skill <unknown>` no longer leaks `bin/ai-find-skills`'s `# full JSON: <tmpfile>` stderr note (the bash download path redirects it to `/dev/null`)
